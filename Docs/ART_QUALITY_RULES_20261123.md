# 《루루 인 비트》 일러스트·UI 제작 품질 기준 — 사용자 요구 고정

적용 범위: 2026-11-23 이후의 캐릭터 신규 컷, 스토리·타이틀 배경, 곡 재킷·곡 일러스트 추가분, 튜토리얼 삽화, 게임·설정·결과 UI, 아이콘·버튼·게이지. 이 파일은 새로운 화면의 창작 기획서나 기존 UI의 교체 허가가 아니다. **다음 작업에서 반드시 지키는 제작·검수 조건**이다.

## 1. 기본 전제 — 캐릭터 2장과 기존 곡 일러스트가 화풍 기준
- 사용자가 올린 **루루 확정 이미지**와 **피노 확정 이미지**를 캐릭터의 외형·작화 기준으로 사용한다. 사용자가 확인용으로 다시 올린 두 이미지를 우선한다.
- 참조 그림 속 **인체·옷·날개 구조에도 오류가 있을 수 있다.** 오류를 복사하지 말고 올바른 인체·의상 연결로 보정하되, 캐릭터 정체성(실루엣·비율·얼굴·머리·옷의 디자인·배색)은 임의 변경하지 않는다.
- **곡 재킷·곡별 일러스트는 현재 프로젝트 폴더의 이미지도 반드시 화풍 기준**으로 사용한다. `Assets/Image2/SongJaket/`, `Assets/Image2/SongIllust/` 원본을 직접 보아 선·면·채도·구도·정보량을 분석한 다음 신규 그림을 만든다. 파일명·GUID만 조사하고 그림체를 확인했다고 말하지 않는다.
- 캐릭터 원본 PNG를 적당한 자리에 **그대로 붙여넣는 것만으로 타이틀·스토리·결과·튜토리얼 신규 일러스트를 완성했다고 주장하지 않는다.** 실제 장면 목적에 맞는 새 포즈·표정·화면 구도를 *같은 화풍으로* 제작한다.

## 2. 그림체: 보존할 것과 제거할 것
**보존**
- 선명하고 일관된 **짙은 자주보라색 외곽선**, 필요한 곳에만 간결한 내부선.
- 형태가 명확한 2D 애니메이션 **셀 채색 1~2단**, 뚜렷하게 나뉘는 넓은 색 면.
- 루루의 나른한 눈매와 긴 짙은 보라 머리의 큰 덩어리 실루엣, 검은 상·하의/넉넉한 연보라 겉옷/고양이형 슬리퍼의 정확한 구조.
- 피노의 짧은 밝은 머리·귀·기하학적 보라 날개, 원본 고유의 소매·깃·목 부위·끈·장식·신발의 정확한 구조.
- 과하게 어린이용이거나 일반적인 AI 미소녀로 바뀌지 않는 **간결하고 개성적인 팝 애니풍**.

**금지**
- 어색한 손가락·손목·팔꿈치·무릎·골반, 손/발 개수 오류, 소매에서 팔이 나오지 않는 연결 오류, 다리 길이 불일치, 공중에 뜨는 옷·악세서리, 원근/시점 모순.
- 옷의 실제 봉제/겹침/개폐를 무시한 임의 지퍼·끈·장식, 엉뚱한 어깨 노출, 허리/반바지/소매 형태가 원본과 달라지는 재디자인.
- 피부·옷·머리의 번들거림, 유리·젤리·크롬·메탈 재질, 과한 광택·광원·네온·글로우·렌즈 플레어·소프트 브러시 번짐.
- 반복되는 가짜 디테일, 의미 없는 삼각형·별·리본·날개·게임패드 장식, 가짜 한글·텍스트, 설명 없이 꾸며 넣은 UI 아이콘.
- 어떤 게임이든 적용 가능한 **보라색 사각형/한쪽 사선 컷**만 반복하는 익명적 UI. **색만 맞춘 것이 화풍 일치가 아니다.**

## 3. 새 캐릭터 일러스트의 필수 검수 순서
1. **정체성 대조:** 원본과 함께 얼굴형/눈 간격/눈꺼풀/머리 앞·옆·뒤 실루엣/옷 길이/배색/장식을 비교한다. 차이가 나면 새 디자인으로 정당화하지 말고 고친다.
2. **포즈와 골격:** 어깨→상완→팔꿈치→전완→손목→손가락, 목→흉곽→골반→허벅지→무릎→발목→발의 방향과 길이를 확인한다. 팔·다리는 옷 아래에서도 해부학적으로 연결되어야 한다.
3. **의상 구조:** 겉옷이 어깨에서 어떻게 걸리고 내려오는지, 소매 안에 손이 실제로 연결되는지, 옷깃·몸판·밑단·반바지·신발이 어디서 겹치는지 대조한다. 몸을 가려서 오류를 덮지 않는다.
4. **작화 일관성:** 선 굵기·색·면 분할·셀 음영·하이라이트 양을 원본 두 그림과 나란히 놓고 확인한다. 한쪽 손/발의 그림 방식이 다른 쪽과 달라지면 수정한다.
5. **화면 기능:** 실제 게임에서 요구하는 포즈·표정·시선·빈 공간이 있어야 한다. 타이틀·대사·성공·실패에 같은 전신을 복붙하는 것은 신규 일러스트 납품이 아니다.
6. **독립 자산:** 캐릭터/배경/UI/텍스트를 합성하지 않은 별도 PNG. 알파 투명과 가장자리 잔여 픽셀 점검.

## 4. 기존 UI는 반드시 먼저 확인하고 재사용·개선한다
- 프로젝트의 `Assets/Image/TitleUI/`에 **기존 버튼, 선택 버튼, 카테고리 선택 박스, 슬라이더, 게이지, 확인창, 로고 등**이 있다.
- 화면의 실제 `RectTransform`, `Image.sprite`, 버튼 `onClick`, 포커스·선택 애니메이션까지 확인하여 **기존 형태와 기능을 보존**한다.
- 기존 것보다 명확히 나은 **구체적인 도안**이 없으면 기존 이미지를 임의로 덮어쓰거나 범용 보라 상자로 대체하지 않는다.
- **개선은 기존 화면의 정체성을 유지하면서** 잘못된 계층·배치·중복·가독성·마우스 조작 문제를 실제로 해결하는 방향으로 한다. 원본 UI의 선·면·색·장식을 먼저 분석해서 일관된 새 부품을 그린다.
- 새 UI는 화면 통째 목업/시트가 아니라 **실제 Unity에서 쓰는 각 기능의 독립 부품**을 제공한다. 프레임/배경/게이지 채움, 슬라이더 트랙/채움/손잡이, 토글 트랙/손잡이 등 분리. 클릭 상태·수치·글씨는 Unity 런타임 처리.
- 공용 부품의 중복 생산은 최소화한다. **기존 초기화 버튼을 새로 만들지 않는다.** 스크롤바가 필요할 때만 트랙 1개+핸들 1개. ESC 일시정지 버튼 상시 HUD 금지.
- 마우스 게임플레이의 원형 노트/접근 링/휠 경로는 현재 코드에서 생성한다. 옛 Q/W/O/P 4레인 키캡·세로 게이지를 신규 디자인의 전제로 삼지 않는다.

## 5. 그림 종류별 실사용 기준
**타이틀**
- 기존 TitleScene의 로고·메뉴·클릭 기능·레이아웃을 실제 확인한다. 기존 그림/배경을 무시하고 게임 화면 전체를 임의 교체하지 않는다.
- 타이틀에 필요한 새 루루 컷은 *새로운 포즈와 상황 표현*이어야 하며, 고유 외형과 인체·의상 구조 정확성 및 우측 상단 로고 공간을 동시에 만족해야 한다.
- 방·콘솔·PC 등 소품은 설정과 실제 공간구조가 맞는 수량만. 물건을 많이 그리는 것이 게임기 콘셉트가 아니다.

**스토리·튜토리얼**
- 화자의 감정과 대사 내용에 맞는 새 반신 컷/표정. 기존 캐릭터와 같은 선질·명암 및 옷 구조를 유지.
- 실제 실습 중 안내가 피노·노트·탄막과 겹치지 않아야 한다. 캐릭터 초상·대화판·배경은 분리.

**곡 재킷과 곡별 배경**
- **기존 `SongJaket`·`SongIllust` 원본을 기준**으로 새 이미지의 붓질/선·면·사물 구조·디테일 수준을 맞춘다. 기존 사용자 이미지 무단 교체 금지.
- 각 곡의 실제 음원을 듣고 무드·시각 소재를 정한다. 곡명만 보고 6곡을 카드·기하 도형으로 도배하지 않는다.
- 재킷과 배경은 다른 목적. 실제 플레이 배경 중심부는 마우스 노트·피노·탄막이 쉽게 읽혀야 하고, 포스터급 화려함을 좇아 플레이를 방해하면 안 된다.

**결과**
- 점수/랭크/판정 내역/기록을 실제 데이터와 연결하는 Unity UI는 별도 레이어. CLEAR/FAILED의 캐릭터 감정 표현은 기존 성공/실패 이미지 검수 후 부족할 때 같은 화풍으로 새로운 컷 제작.
- 결과 화면의 장식 이미지보다 **점수·랭크의 위계와 캐릭터 표정**이 먼저 읽혀야 한다.

**설정·게임 HUD**
- 플레이 영역에서 사용자의 시선과 마우스 입력을 방해하지 않는 배치.
- 설정은 왼쪽 카테고리 버튼·오른쪽 실제 Slider/Toggle을 우선. 각 그림만 존재하고 눌리지 않으면 실패.
- 안정화 UI는 실제 마우스 모드 레이아웃에 맞춘 프레임/트랙/채움 **3개를 분리**. 옛 4레인용 게이지 재사용 금지.

## 6. 조사와 결과물의 품질 책임
- 사용자가 여러 차례 **수많은 실제 상용 리듬게임의 화면을 확인하라**고 요청했다. 임의 색상 제안/게임 이름 몇 개 나열/대충 흉내 낸 네모 도면은 조사 완료가 아니다.
- 실제 스크린샷/게임 화면에서 정보 배치·연출·곡 선택·텍스트·시각 계층을 비교한 후, **우리 게임에서 구체적으로 무엇을 개선하는지** 작품별로 결정한다. 다른 게임 UI를 베끼지 않는다.
- 결과물이 사용자의 기준에 부족하면 “기준 미달이라 종료”로 마무리하지 않는다. **문제 지점 수정 → 새 결과 확인 → 필요하면 계속 수정**하며 요청된 작업을 추진한다.
- 조사·명세서·시안·이미지·GitHub 커밋·Unity 연결·실제 플레이 검수는 **각기 다른 완료 단계**다. PNG 미제작 또는 실행 미검증이면 그대로 밝혀야 하며, 문서를 늘려 실제 제작을 대체하지 않는다.
- 외형 검수 예: 인체/의상 연결, 원본 대비 선과 셀 면 분할, 기존 그림 옆에 놓았을 때 이질감, 알파 가장자리, UI 텍스트 비침, 작은 표시 크기. 눈으로 확인하지 못한 이미지는 화풍 일치라고 단정하지 않는다.

## 7. 변경 금지 항목과 승인 조건
- 사용자가 확정한 루루·피노 외형, 기존 UI/곡 이미지 원본 파일·GUID, 플레이 입력·판정·노트 종류·피노 동작의 기획을 사용자가 요청하지 않은 범위에서 바꾸지 않는다.
- **새 디자인 제시 = 기존 기능 폐기 허가가 아니다.** 기존 장면·코드에 어떤 Image를 새 Sprite로 연결할지 명시하고 원본을 보존한다.
- 생성 결과에 구조 오류가 발견되면 **같은 잘못을 반복하지 않도록** 원본 비교 후 다시 그린다. 과장된 “완성” 표현 금지.

---

**핵심 고정 조건:** “루루·피노와 기존 곡 일러스트의 개성적인 2D 애니풍을 유지하되, 인체·의상·사물·UI 구조를 더 정확하게, AI 특유의 과한 장식과 부자연스러움 없이 실제 상용 PC 리듬게임에서 쓸 수준으로 제작한다. 기존 UI를 확인한 뒤 재사용하거나 확실히 개선하고, 그림 제작 결과와 Unity 연결·검증까지 수행한다.”
