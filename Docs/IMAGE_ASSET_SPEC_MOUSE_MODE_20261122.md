# 《루루 인 비트》 전체 게임 이미지 제작·사용 명세서 v3

**작성 기준:** 2026-11-22 / GitHub `main` / Unity 2022.3 / PC 16:9 마우스 전용 리듬·탄막 게임  
**사용자 제공 확정 그림 기준:** 2026-11-22 업로드된 첫 이미지 = **루루**, 두 번째 이미지 = **피노**. 두 인물의 외형·옷·머리 실루엣·얼굴·등신·날개 등은 새 이미지에서도 보존.  
**문서의 성격:** 게임 전체의 *아트 제작 요구사항 + Unity 적용 설계*. **이미지가 제작됐다는 뜻도, 화면이 완성됐다는 뜻도 아니다.**

> **범위:** 타이틀, 스토리·프롤로그, 튜토리얼, 곡 선택, 플레이 배경/게임판/HUD, 바이러스/피노, 일시정지, 결과, 설정, 크레딧, 로딩. **이 중 신규 그림이 필요하지 않은 항목까지 무엇을 재사용하고 코드로 처리할지 기록한다.** 숫자는 발주 수가 아니라 실제 슬롯 수와 상태다.

## 0. 가장 중요한 원칙 — '전체 이미지를 다 만든다'는 뜻

1. **게임 안의 용도가 먼저**다. 씬/화면/이미지 컴포넌트가 정해지지 않은 장식용 버튼·별·게임패드·슬롯·틀을 시트에 임의로 채우지 않는다. '한 장에 잔뜩 그려서 나중에 썰기' 대신 사용처가 확인된 **부품마다 개별 투명 PNG**.
2. **독특하고 팝한 2D 애니메이션 리듬게임 UI.** 루루의 머리처럼 큰 실루엣, 피노의 의상처럼 절제된 비대칭과 셀 명암을 UI에 반영한다. 단, 캐릭터 머리·날개·게임패드 그림을 프레임 양끝마다 붙이지 않는다. **의미 있는 색 면 분할과 빠른 반응, 큰 점수·리듬 정보**가 독특함의 주역이다.
3. **유아용 장난감 UI / 모바일 가챠 UI / 메탈 SF 계기판 / 네온 글로우 / 보라색 유리 패널 금지.** PC 전용, 여백과 타이포그래피가 또렷한 애니메이션 리듬게임을 만든다.
4. **마우스 노트는 이미지로 다시 만들지 않는다.** 기존 `MouseModeChartPlayer.MakeSprites()`의 원형 노트·접근 링·좌/우/휠 입력형 표시를 유지한다. **새 노트 PNG 0장**. 구형 Q/W/O/P 4레인용 보드/노트/판정선을 마우스 모드에 넣지 않는다.
5. **기존 안정화 게이지 `Assets/Image/안정화게이지.png`, `안정화게이지2.png`는 구형 4레인 전용이므로 사용 불가.** 현재 마우스 화면에는 새 게이지의 프레임/빈 배경/속 막대가 각각 필요하다.
6. **파일이 있다는 사실만으로 '쓸 수 있는 이미지'라고 판정하지 않는다.** `TitleScene`의 기존 타이틀 UI, `SongSelectScene` 구성, 결과창 런타임 대체 UI는 화풍·배치·가독성을 Game View로 보고 평가해야 한다. 기존 버튼도 부적합하면 **공용 이미지로 교체**하되 같은 기능의 PNG를 새로 여러 개 만들지 않는다.
7. **이 프로젝트의 그림체 기준은 두 캐릭터 이미지 자체.** 루루는 매우 긴 어두운 자주보라 머리·나른한 보라 눈·검은 상의·오버사이즈 밝은 겉옷과 고양이형 슬리퍼, 피노는 짧은 은백/연보라 머리·뾰족한 귀·두 개의 큰 라벤더 날개·흰/보라 의상·검은 목둘레/장식. 임의로 의상 부품을 더하거나 빼지 않는다.
8. **숫자와 글씨를 PNG에 그리지 않는다.** 점수, 콤보, 판정, 노트 문자(L/R/W), 한글 대사, 스토리 진행, 곡 제목, 결과 랭크, 설정 수치는 TMP/Unity 코드로 출력한다.
9. **정해지지 않은 스토리를 이미 확정된 것처럼 그리지 않는다.** 루루·피노·게임을 하는 콘셉트·바이러스는 사용자가 설정한 축이다. 아래 배경 스케치의 세부 사건은 *잠정 연출안*이다. 스토리 기획 확정 전에 인물 얼굴·장면을 강제로 양산하지 않는다.

## 2. 하나의 디자인 언어 — 모든 PNG 공통

### 2.1 색과 선

| 역할 | 작업용 색상 제안 | 사용 원칙 |
|---|---|---|
| 외곽선 | `#261937` | 완전 새까만 선보다 따뜻한 자주보라. 선 두께는 1920×1080에 적용했을 때 약 **2~4px로 체감** |
| 어두운 받침 | `#433055` | 버튼/판정판/게이지 안쪽처럼 깊이가 필요한 구간만 |
| 중간 보라 | `#71558E` | 선택 대비, 낮은 면 1단 |
| 연라벤더 | `#CEB8F5` | 주요 팝 컬러, 빈 판을 전부 칠하지 말고 가장자리와 강조에 분배 |
| 크림빛 연보라 | `#F6F0FC` | 텍스트를 올리는 밝은 면 |
| 소량의 포인트 핑크 | `#F2A9CE` | 아주 작은 선택 포인트/게이지 위험 대비. 화면 전체 도배 금지 |
| 보조 민트 | `#A2DFD4` | **필요할 때만** 판정 성공·선택 상태 등 소량. 과한 형광 느낌 금지 |

이 색상은 **확정 루루·피노 원본을 보고 최종 색 뽑기를 하기 전의 제작 가이드**다. 지금 화풍과 다른 보라톤이 나오면 숫자보다 원본이 우선한다.

- 외곽선과 그림자 면은 **셀 애니메이션처럼 경계가 또렷한 1~2단**, 에어브러시·유리·크롬·홀로그램·광원 번짐은 금지.
- **한 부품에 작은 비대칭 포인트 1곳** 정도만 사용: 한 귀퉁이의 짧은 대각 절개, 리듬 바의 한쪽 절단면, 짧은 색 띠. 매 모서리 별/날개/십자가 장식 금지.
- 선/모서리는 단순하고 자신감 있게. 캐릭터처럼 약간 생동감 있는 실루엣이지만 GUI 값/글자를 읽는 데 방해되지 않도록 한다.
- 버튼과 패널을 전부 짙은 보라로 채우지 않는다. *밝은 면 + 어두운 외곽/텍스트*와 *어두운 면 + 밝은 텍스트*의 대비를 섞어 화면의 리듬을 만든다.

### 2.2 파일 공통 기술 규격

- **한 파일 한 기능**: PNG 32-bit RGBA, 픽셀 알파 실제 투명. `Sprite (2D and UI)`, `Single`, `Alpha Is Transparency` 사용. 숨겨진 흰 배경, 회색 체크무늬, 가짜 PNG 투명 처리 불가.
- **투명 픽셀 끝자락:** 프레임 외부에 분홍/푸른 글로우·먹물 번짐·배경 잔상 금지. 외곽선은 알파 경계 안에서 깔끔하게 닫히고, 잘린 선 없음.
- **원본 제작 크기 ≠ Unity 표시 크기.** 기준 CanvasScaler는 1920×1080이다. 이미지가 640px인 것은 640px에만 표시하라는 뜻이 아니다.
- **9-slice**: 패널·버튼·길게 늘릴 수 있는 틀/트랙에서 모서리 부분은 고정하고 가운데는 한 톤의 평평한 면. 가장자리 안쪽 장식이 9-slice 중앙을 가로지르면 실패. Unity Sprite Editor Border를 실제 그림 단위로 설정한 후 `Image.Type=Sliced`.
- **알파와 텍스트**: 투명 프레임이라도 내용을 넣을 내부 면은 충분한 불투명도/대비 확보. 한글 TMP가 올라갈 곳은 처음부터 **문구가 들어갈 폭과 높이**를 비워 둔다.
- **상태 피드백은 코드**: Hover, Pressed, Disabled, Focus, Success, Error, Fill, Combo Pop, FAST/LATE 등은 Image Color/RectTransform/Animator로 만든다. 색만 다른 PNG 중복 생산 금지.
- **해상도 테스트**: 1920×1080, 1600×900, 1366×768 이상에서 대화창·안내창·버튼·게이지가 잘리지 않는지 확인. 게임판 안의 노트, 피노, 탄막은 이 UI보다 우선한다.
- **Unity 최소 체크**: `raycastTarget=false` for 장식용 Image. 버튼 Image만 Raycast 받는다. UI 프레임이 마우스 노트 입력을 막거나 피노 이동을 방해하면 실패.
- **작업 경로(신규 제안)**: `Assets/Art/Production/UI/`, `Tutorial/`, `Characters/`, `SongJackets/`, `SongBackgrounds/`, `Story/` 하위. 실제 생성·연결 전에는 이 폴더가 존재한다고 주장하지 않는다.
- **완성품 납품 기준**: 단독 PNG 각각 + 스프라이트 임포트 설정 + 게임 씬에 연결된 작동 증거. 총괄 시트 목업은 참고 이미지일 뿐 납품품 아님.

## 3. 공용 UI 5개 — **각각의 구체적인 그림 제작법**

### UI-01. `UI_Panel.png` — 모든 대화/결과/일시정지/확인 창 공용

- **원본**: 640×256px RGBA, Sprite Single. 기준 9-slice 영역 예시 Left/Right=48~64px, Top/Bottom=36~48px. 모서리 디자인에 따라 실제 border 조정.
- **실루엣**: 폭이 긴 둥근 사각형을 기본으로, **오른쪽 위 또는 왼쪽 아래 한쪽만 살짝 사선 절개**. 모든 귀퉁이가 돌출되거나 삐죽 튀어나오면 안 됨. 전체 외형이 아니라 선 하나/절단면으로 팝한 포인트를 줌.
- **색 배분**: 외곽선 얇은 짙은 보라. 내부는 밝은 연보라가 75~85%, 모서리/상단에 중간 보라 1단 10~15%. 크게 비어 있는 콘텐츠 영역 확보.
- **콘텐츠 안전 영역**: 스프라이트 가장자리 기준 **좌우 9%, 상하 15% 이상**은 글자/버튼이 침범하지 않을 여백. **중앙 70~80%는 패턴 없는 평면**. 캐릭터 초상 위치가 스프라이트에 그려져 있으면 안 됨.
- **그리지 않을 것**: 말풍선 꼬리, 루루/피노 얼굴, 게임패드, 별, 숫자, 대사, 버튼, 배경 전체, 좌우 모두 있는 큰 날개, 이중 프레임, 광택.
- **실사용 네 곳**: `TutorialConversation/DialoguePanel`(가로 긴 대사), `TutorialGuide`(작은 안내), `ResultPanel_Runtime`의 중앙 정보 영역, `PausePanel`/일반 확인창. **서로 다른 4가지 크기로 늘려도** 같은 선 굵기/모서리 형태가 유지돼야 함.
- **테스트**: 대화창 1250×290, 가이드 450×240, 결과 통계창 1100×650, 작은 확인창 520×260 렌더링 테스트. 그림이 이 비율 차이를 못 견디면 그 장식은 제거한다.

### UI-02. `UI_Button.png` — 다양한 액션에 쓸 공통 버튼 1장

- **원본** 320×96px RGBA, Border L/R 38~48px, T/B 22~28px 권장. 글자/아이콘을 넣지 않는다.
- **모양**: 짧고 넓은 누름 영역. 왼쪽/오른쪽 각각 과하게 뾰족한 화살표처럼 만들지 않음. 하단에 1단 어두운 받침선, 윗면은 밝고 평평함.
- **안전 영역**: 중앙 68% 이상은 글자만 올라갈 수 있는 평면. 3~6자 한글까지 버튼폭 변경 시 잘 읽히도록 설계.
- **상태는 원본 1장만**: 기본 밝은 라벤더, Hover 스케일 1.04와 색상 톤 조정, Pressed scale 0.97, Disabled 불투명도 0.4. Hover를 위한 빛줄기, 별, 별도 버튼 PNG 금지.
- **실사용**: 튜토리얼 다음/계속/연습 시작/다시 연습/곡 선택, 결과 RETRY/SONG SELECT, 설정 저장/취소, 확인/나가기. **같은 파일 재사용**.
- **기능**: Unity `Button.targetGraphic=Image`, `Image.Type=Sliced`; 라벨은 자식 TMP. 클릭 영역이 1366×768에서도 너무 작지 않게 배치.

### UI-03. `Stability_Frame.png` — **마우스 전용** 안정화 외곽

- **원본**: 768×88px, 투명, 9-slice(권장 양 끝 48~60px 보호). 게임 화면에서 가로 420~650px 정도에 맞춰 적용할 수 있는 구조.
- **형태**: 얇은 가로 바의 가장자리만. 슬림한 짙은 보라 실루엣과 상단/하단 1단 라벤더 면. 장식은 한쪽의 작은 사선 절단만.
- **내부**: **투명하게 비워** 뒤에 `Stability_Track.png`가 보이게. 내부를 채색해서 트랙과 합쳐 놓으면 별도 게이지로 쓰기 어려움.
- **금지**: 4레인 세로 게임판과 맞물리는 세로 프레임, 누적 단위 눈금, 큰 캐릭터 얼굴, 밝은 광택/네온.
- **적용**: `GameplayCanvas/HUDLayer`의 **게임 노트와 피노 경로 밖**, 튜토리얼과 일반 플레이에서 같은 프레임을 사용. `MouseModeBulletDirector`의 안정화 값과 연동, 적에게 맞았을 때 GUI가 동일 값으로 변함.

### UI-04. `Stability_Track.png` — 안정화의 빈 바닥

- **원본**: 724×44px, RGBA, 9-slice(양 끝 18~26px).
- **형태**: 짙은 보라/밤색 단일 채움, 외곽선은 매우 얇게. 양끝은 프레임과 충돌 없이 빈 공간을 남김.
- **중앙 90%** 패턴 없이 균일한 색. 능동적으로 커졌다 줄었다 할 부분은 여기가 아니라 Fill 이미지.
- **적용**: Frame 뒤/안쪽에 고정되는 Image, Fill보다 아래 레이어. 표시 폭/높이에서 Fill보다 약간 큰 여백으로 감싸기.
- **금지**: 미리 그려진 꽉 찬 막대, 100% 색, 숫자, 격자무늬, 작은 점멸 요소.

### UI-05. `Stability_Fill.png` — 실제로 줄어드는 채움

- **원본**: 700×30px RGBA Sprite Single. **가로 방향으로 균일한 평면 컬러**, 세로 방향 1단 셀 명암만 허용. 입체감/그라데이션 금지.
- **위치**: Track 위에 겹쳐짐. Frame이 모서리를 덮도록 Track과 Fill은 프레임보다 작게 배치.
- **핵심 주의**: `Image.Type=Filled / Horizontal / Origin=Left`로 잘라 쓰므로, **오른쪽 끝을 잘라도 시각적으로 깨지지 않는 형상**이어야 한다. 거대한 마름모 끝/장식/얼굴/눈금 금지.
- **연출**: 100/60/20/0%에 맞춰 `fillAmount` 감소, 위기 색상 전환은 런타임 `Image.color`, 반짝임이 아니라 짧은 밝기/알파 변화만 사용.
- **테스트**: 1%, 20%, 60%, 100%에서 찢어진 끝·남는 픽셀·중복 백그라운드가 없어야 함. 기존 `Stability_Runtime`의 회색 바닥 UI와 **동시에 두 개가 뜨면 실패**.

### 공용 UI로 해결할 화면

- **타이틀·설정**: 실제로 맞지 않는 기존 버튼/프레임만 UI-01·UI-02로 교체. 기존 로고/메인 이미지까지 자동 교체하지 않는다.
- **결과**: 넓은 화면 안에 UI-01 정보창 + UI-02 버튼 두 개, 큰 콤보/점수는 별도 TMP. 점수 정보가 시각적으로 두드러지도록 크기·위치·짧은 애니메이션을 조정한다.
- **일시정지**: UI-01 안에 TMP PAUSED 및 선택지. ESC로 열고 닫기, 상시 화면에 PAUSE 아이콘 추가하지 않음.
- **확인/종료/크레딧**: 동일 패널/버튼을 크기와 자식 텍스트만 바꿔 사용.
- **설정 스크롤 바**: `Settings_Scroll_Track.png` + `Settings_Scroll_Handle.png`는 **실제 ScrollRect 필요성이 확인되는 경우** 아래 조건부 명세로 제작. 단순 슬라이더와 동일한 이미지라고 가정하지 않는다.

## 5. 캐릭터 이미지 — 루루/피노 **원본 분리 2종 + 기존 애니메이션**

### C-01 `Character_Lulu_Dialogue.png` — **새로 그리기보다 원본에서 분리**

## 6. 곡 선택 재킷 6종 — **각 곡별 독립 일러스트 지시**

**모든 재킷 공통**
- 1024×1024, 정사각형 불투명 PNG 가능. **캐릭터·기하학 아트·소품을 1개의 명확한 중심 콘셉트로 구성**하되, 재킷 속에 UI의 버튼/곡명/레벨/점수/가짜 한글을 넣지 않는다.

## 8. 스토리 / 프롤로그 — 출시용 기본 배경 2종

**스토리 전용 Unity 씬은 아직 없음.** 아래 두 장은 루루/피노/바이러스라는 현재 설정을 바탕으로 한 **최소 비주얼 패키지 제안**, 스토리의 사건·대사·챕터 수가 확정됐다고 주장하지 않는다. 캐릭터는 **그림 배경 안에 굽지 말고 C-01/C-02의 분리 초상으로** 표시한다.

### ST-01 `Story_LuluRoom.png` — 루루가 게임하는 공간
- **원본**: 1920×1080 불투명 배경.
- **공간**: 루루가 좋아하는 **PC 게임/리듬게임을 즐기는 방**. 작은 책상, 모니터, 게임 관련 소품을 정리된 애니메이션 배경으로 묘사. 사용자가 원치 않은 과도한 방 구조/기계 장치/온통 네온 디스플레이 금지.

## 11. 인게임 적용 전 점검과 실제 완료 판정

### 이미지별 납품 검사
- [ ] 명세서의 **각 사용처를 설명할 수 있는 이미지**만 제작했는가. 시트 채우기용 장식 PNG 0장.
- [ ] 기능성 UI는 **한 기능 = 한 파일**이고 투명 배경의 깔끔한 픽셀을 가지는가.
- [ ] 실제 9-slice 작업에서 모서리가 640×256 → 1250×290, 450×240으로 늘려도 변형되지 않는가.
- [ ] 루루/피노는 제공된 정확한 원본을 기준으로 분리했는가. 머리/의상/체형/날개 재설계나 흰 배경 잔류가 없는가.
- [ ] 4레인 안정화 게이지 PNG와 기존 4레인 노트 PNG가 최신 화면의 신규 자산으로 들어오지 않았는가.
- [ ] 노트는 여전히 **코드 원형/접근 링/휠 노트**이며 새 PNG로 교체되지 않았는가.
- [ ] 곡 재킷 6개가 실제 차트의 `songSelectJacket`와 맞게 연결됐는가. 기존 2장을 제대로 검수했는가.
- [ ] 곡 배경을 설정해도 플레이 중앙의 노트와 피노, 적의 경고가 항상 가장 눈에 띄는가.
- [ ] Story 이미지가 인물·대사를 굽지 않은 **분리 레이어**이며 다른 이야기 구간에 재사용 가능한가.
- [ ] 모든 텍스트가 TMP, 버튼 상태/게이지 값이 코드로 변하는가.
- [ ] 1920×1080, 1600×900, 1366×768 게임 화면에서 누름/읽음/재시도가 정상인가.
- [ ] 실제 게임에서 선택/피격/점수/노트 판정/일시정지/튜토리얼/결과의 입력을 새 UI가 방해하지 않는가.

### 제작·적용 순서 — 디자인과 개발을 함께 진전시키는 방식

1. **현재 UI 재고 검수**: TitleScene·SongSelectScene·Mouse 씬 Game View를 확인하고 `A9_*`, 콤보·점수, 2장 SongJaket의 실물을 판단한다. '있음'과 '쓸 만함' 구분.
2. **공용 패널·공용 버튼**: **2개** PNG 각각 독립 파일 제작, 실제 Tutorial/Result/Pause/Title UI에 9-slice 통합.
3. **안정화 게이지**: **3개** PNG를 따로 제작하고 실제 안정화 값에 연결. 4레인 세로형 완전 제외. 기존 임시 안정화와 중복 표시 방지.
4. **튜토리얼**: 마우스 아이콘 **4개** 제작 + 루루·피노 투명 초상 분리, `TutorialGuide`를 이미지 슬롯과 연결. 대사창 진행/게임 조작 동시 검증.
5. **곡 선택**: 기존 재킷 확인 후 6곡별 **필요한 만큼만** 재킷 제작 및 차트에 실제 연결. 재킷 교체·프리뷰·난이도·스크롤 동작 검증.
6. **플레이 배경**: 현재 공통 BG가 부족하면 곡별 **최대 5개**를 제작하고 PlayArea 가독성 검증. 재킷을 그냥 확대하지 않는다.
7. **스토리/타이틀**: 루루 방·이상현상 2개 배경을 확정된 프롤로그와 연결. 기존 타이틀 일러스트가 부적합할 때만 별도 루루 키비주얼을 만든다.
8. **결과·설정·크레딧 최종 조립**: 기존 피노 Clear/False, TMP, 공용 패널/버튼을 사용. **정말 필요한 조건부 자산만** 추가.
9. **모든 신규 이미지가 씬/코드에 연결됐는지 전수 검사**. Unity에서 사용되지 않는 일러스트/아이콘이 남아 있으면 제작 목록에서 제외하거나 실제 사용처를 명확히 한다.

**마지막 기준:** 필요한 모든 화면을 다룬 **전체 게임 아트 명세서**이지만, **모든 이미지가 다 만들어졌다는 완료 주장도 아니고, 모든 슬롯을 무조건 별도의 새 이미지로 채우라는 지시도 아니다.** 제작 결과는 *캐릭터 화풍 일치 + 실제 화면 사용 + 입력/가독성 검증*으로 판정한다.
