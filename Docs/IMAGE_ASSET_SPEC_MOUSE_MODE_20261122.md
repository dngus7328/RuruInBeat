# 《루루 인 비트》 UI 이미지 실사용 제작 명세서 (간결판)

**적용 대상:** PC 전용 마우스 리듬게임 / Unity 2022.3 / 1920×1080 기준 Canvas  
**기준 캐릭터:** 사용자가 2026-11-22에 다시 올린 **루루(짙은 보라 긴 머리·나른한 표정)**, **피노(연라벤더 짧은 머리·보라 날개)** 원본 이미지 두 장. 캐릭터 재디자인 금지.  
**이 문서는 제작 지시서이며, 아래 신규 PNG는 아직 생성·Unity 연결되지 않았다.**

## 1. 목표 — 장식품이 아니라 실제 UI 부품

**핵심:** 독특하고 팝한 **2D 애니메이션 리듬게임**의 표정은 유지하되, **실제 게임 화면을 가리지 않고 모든 제작 이미지가 Unity에서 분리 사용**되어야 한다.

- **이미지 1장 = 실제로 사용할 기능성 부품 1개.** 커다란 이미지 시트에 다른 버튼·프레임·아이콘을 한꺼번에 붙이지 않는다.
- 같은 프레임은 대화창·안내창·결과창·일시정지창에 **공용 9-slice**로 재사용. 화면마다 새 프레임을 양산하지 않는다.
- 버튼은 공통 이미지 하나를 재사용하고, 호버·눌림·선택·비활성은 **Unity 색상/스케일 애니메이션**으로 만든다.
- **배경/프레임/채움/캐릭터/텍스트는 다른 오브젝트**로 다룬다. 한 이미지에 여러 기능을 굽지 않는다.
- 절제된 팝 스타일: 살짝 엇갈린 모서리, 간결한 사선·컷아웃 1곳, 분명한 면 분할, 박자감 있는 짧은 상호작용. **별·날개·리본·게임패드 장식을 사방에 붙이지 않는다.**
- **PC 리듬게임의 정보 우선순위:** 노트·탄막·피노가 1순위, 안정화와 콤보/점수가 2순위, 대화·선택 UI가 3순위. 장식으로 플레이를 가리지 않는다.

### 디자인 기준

| 항목 | 구체적인 기준 |
|---|---|
| 형태 | 기본은 가로로 긴 직사각형. 한쪽 모서리에만 작은 사선 절개/비대칭 포인트. 모든 모서리를 날개나 별로 만들지 않는다 |
| 선 | 얇고 일정한 짙은 자주색 외곽선, Unity 1920×1080 표시에서 약 2~4px 체감. 두꺼운 이중·삼중 테두리 금지 |
| 색 | 루루의 짙은 보라 + 피노의 밝은 라벤더 + 밝은 크림빛 흰색. 연분홍은 **작은 선택/강조 부분에만**. 화면 전체 보라색 덩어리 금지 |
| 명암 | **단색 1~2단 셀 셰이딩**. 재질이 유리·금속·젤리처럼 보이는 그라데이션, 네온·바깥 글로우·거대한 그림자 금지 |
| 팝한 리듬감 | 선명한 대비·비대칭 실루엣과 런타임 0.1~0.2초 팝 반응으로 표현. 이미지 안에 효과를 미리 그리지 않음 |
| 글씨 | 모든 버튼·대사·점수·콤보·게이지 수치·라벨은 Unity TMP. PNG에 한글·영어·숫자 삽입 금지 |
| 공통 배경 | 실투명 RGBA PNG. 흰색 바탕, 검은 배경, 체크무늬, 잘라낼 수 없는 그림자 및 번진 컬러 테두리 금지 |

색상 견본(확정 캐릭터 이미지와 게임 뷰에서 최종 비교): 외곽선 `#261A3B`, 깊은 보라 `#594277`, 라벤더 `#C6AEF0`, 밝은 면 `#EFE7F9`, 소량의 핑크 포인트 `#E6B3D7`. 단순히 이 다섯 색을 다 칠하라는 의미가 아니다.

## 2. 신규 공용 UI **5개 PNG만** 먼저 제작

기존 문서의 **18장 무조건 제작 지시를 폐기**한다. 아래 5장은 모두 독립된 투명 PNG이며, 각각 명확한 적용 대상이 있다. 크기는 **원본 제작 캔버스 권장치**이지 Unity 표시 크기를 고정하는 값이 아니다.

| ID | 독립 PNG | 권장 원본 크기 | 정확한 구성과 실제 사용처 |
|---|---|---|---|
| UI-01 | `UI_Panel.png` | 640×256, 9-slice | **공통 패널 1개.** 비대칭 절개는 **한 모서리 1곳**, 가운데는 넓은 단색 콘텐츠 영역. **튜토리얼 대화창·작은 단계 안내창·결과 통계창·일시정지창**에 크기만 바꿔 사용. 인물·글씨·버튼은 포함하지 않음 |
| UI-02 | `UI_Button.png` | 320×96, 9-slice | **글자/아이콘 없는 버튼 1개.** 튜토리얼 다음·건너뛰기·다시하기, 결과창 재시도/돌아가기, 설정 확인 등에 공용 사용. 선택 상태는 `Button` Color Tint와 애니메이션 |
| UI-03 | `Stability_Frame.png` | 768×88, 9-slice | **마우스 모드 전용 안정화 게이지의 바깥 테두리만.** 가로로 길고 가볍게. 내부 막대, 표시 수치, 캐릭터 얼굴, 날개 장식 없음 |
| UI-04 | `Stability_Track.png` | 724×44, 9-slice | **게이지의 빈 배경 한 겹만.** 어두운 내부 바탕, 충전량/색상 변화 없음. UI-03 안에 겹쳐 사용 |
| UI-05 | `Stability_Fill.png` | 700×30, Single | **수치에 따라 줄어드는 채움 막대만.** 분리된 단순 평면 그래픽. 반짝이는 끝 장식이나 양 끝에 튀어나오는 장식 금지. `Image.Type=Filled / Horizontal / Origin=Left`와 호환 |

**왜 5장인가?** 대화창·단계 안내창·결과창마다 새 프레임을 만들 필요가 없다. 1개의 **공통 패널**과 1개의 **버튼**이면 해당 화면을 구성할 수 있고, 안정화 게이지는 사용자가 이전부터 요청한 대로 프레임·빈 트랙·막대를 **반드시 3개로 분리**해야 하기 때문이다.

> **주의:** `Assets/Image/안정화게이지.png`, `안정화게이지2.png`는 **기존 4레인 세로형 게임의 이미지라 사용 불가.** 새 게이지는 현재 마우스 게임 화면에 맞춘 **새로운 가로형 3분리 이미지**다. 플레이 영역을 가리는 위치라면 배치부터 수정한다.

### Unity에서 실제로 연결할 자리

| 컴포넌트 | 코드/씬의 구체적 적용 위치 | 재사용 |
|---|---|---|
| `UI_Panel.png` | `MouseTutorialController.BuildDialogue()`의 `DialoguePanel`; `BuildGuide()`의 `TutorialGuide`; `MouseModeResultFlow.BuildFallbackPanel()`의 결과 정보 영역; `PausePanel` | **최소 4곳** |
| `UI_Button.png` | `MouseTutorialController.CreateButton()` 및 결과창 버튼. 타이틀/설정 기존 버튼 이미지는 일단 유지, 이후 동일 스타일 필요 시 이 PNG로 대체 | **다수 재사용** |
| `Stability_*.png` | `MouseModeBulletDirector.EnsureStabilityDisplay()`의 기존 `Stability_Runtime` 임시 직사각형을 정식 게이지 구성으로 교체 | **마우스 플레이 + 튜토리얼** |

실제 Game View 확인 전에는 기존 플레이 게임기 프레임(`Assets/Image2/Lulu_UI_Frame_Light_Transparent.png`)을 임의로 교체하거나 화면 전체를 새 UI 시트로 덮지 않는다.

## 3. 새 UI 그림으로 만들지 않을 것

| 요소 | 처리 방식 |
|---|---|
| **마우스 노트·접근 원·휠 경로** | 사용자가 요구한 `MouseModeChartPlayer.MakeSprites()`의 **런타임 코드 생성 방식 그대로 유지**. **신규 노트 PNG 0개** |
| 콤보·점수·판정·FAST/LATE·안정화 수치·진행도 | Unity TMP 및 기존 런타임 로직 |
| 경고·선택·게이지 색 변화·버튼 호버 | Unity 색·크기·알파·애니메이션 |
| 키보드 4레인 UI, D패드, 별도 세로형 게이지 | **만들지 않음**. 현재 조작과 다름 |
| 장식용 십자·별·날개·십여 개의 조작 아이콘 | **만들지 않음**. 필요한 기능이 없는 이미지라면 납품하지 않음 |
| 슬라이더·토글·리바인드 등 | 기존 `Assets/Image/TitleUI`에 사용 가능한 부품 있음. 지금 동일 기능 PNG를 중복 생산하지 않음. 단 구형 4레인 키 재설정 화면은 이미지 문제가 아니라 기능 제거/정리 대상 |
| 루루·피노 초상 | 이 대화에서 제공된 **확정 캐릭터 원본 이미지 사용**. 새 캐릭터 얼굴·의상 생성 금지. 초상은 원본에서 잘라 사용, 기존 피노 애니메이션은 유지 |
| 게임플레이용 적 `Enemy01`, 탄막 | 기존 게임 자산/런타임 표현을 우선 유지. 쓰임없는 탄막 이미지 추가 금지 |

## 4. 별도 콘텐츠 그림: 곡 재킷 6종

재킷은 **공용 UI 5장과 다른 콘텐츠**이며, 한 장씩 `SongSelectScene`에서 곡 선택 시 표시되는 **실제 지정 슬롯**이 있다. 따라서 사용되지 않을 장식 패널과 다르다.

| 음원/차트 | 필요한 이미지 슬롯 |
|---|---|
| BOOTBEAT | `Jacket_BOOTBEAT.png` |
| Oddbeat Shuffle | `Jacket_OddbeatShuffle.png` |
| Full-Band Hit | `Jacket_FullBandHit.png` |
| 瞬奏 -SHUNSOU- | `Jacket_SHUNSOU.png` |
| Cotton Pulse | `Jacket_CottonPulse.png` |
| Pop'n Dash | `Jacket_PopnDash.png` |

- 정사각형 **1024×1024 PNG**, 한 그림 = 한 곡. 곡의 음악적 분위기를 반영하되 대사/가짜 로고 텍스트를 넣지 않는다.
- **기존 `Assets/Image2/SongJaket/`에 2개 이미지가 보유 중이므로 그림 내용을 먼저 확인**하고 해당 곡에 적합할 때만 재사용. **무조건 6장을 새로 만들지 않음**.
- 최종 연결은 곡별 `MouseModeChartAsset.songSelectJacket`에만. 선택 메뉴와 곡별 차트가 동일 재킷 사용, 난이도마다 중복 이미지 제작하지 않음.

## 5. 이미지 생성·분리·검수 합격 조건

**한 장의 시트 예시를 만들어 보여주는 것과 사용 가능한 UI 파일을 납품하는 것은 다르다.** 합격 결과물은 아래 모두 만족해야 한다.

1. **UI 5개가 각각 별도 PNG 파일**. 큰 시트에서 겹쳐 잘라 쓰는 방식 금지. 이미지 모서리끼리 붙거나 겹침 없음.
2. 배경이 **진짜 투명 알파**인지 확인. 흰 바탕, 검은 바탕, 분홍/파란 테두리 번짐, 체크무늬가 픽셀에 구워진 PNG는 실패.
3. 모든 프레임은 **중앙에 글씨와 기능을 놓을 충분한 빈 공간**이 있다. 기하학적 모서리 장식이 내용 영역을 침범하면 실패.
4. `UI_Panel`, `UI_Button`, `Stability_Frame`, `Stability_Track`는 **9-slice 가능**해야 한다. 중앙을 늘려도 외곽선/각진 끝/셀 명암이 찌그러지지 않음. Unity Sprite Editor의 Border는 실물 가장자리 두께에 맞춰 설정.
5. 버튼은 1개의 원본으로 **기본·호버·눌림·비활성**을 코드에서 구현. 같은 버튼을 색만 바꾼 PNG 3~6개로 양산하지 않는다.
6. 안정화 게이지는 **frame / track / fill을 실제 3개의 Image 컴포넌트**에 연결해 100/60/20/0%가 정상적으로 표시되고, 중복 `Stability_Runtime` UI가 남지 않아야 한다.
7. `UI_Panel`은 **가로 긴 대화창과 작은 안내창, 결과창**에서 각각 써 보고 찌그러짐·가독성·피노/노트 가림이 없음을 확인한다.
8. 현재 게임 전체와 **같은 애니메이션 그림체**. 2~3개의 굵고 튀는 장식으로 시선을 빼앗는 디자인, 대형 게임패드 장식, 네온 글로우가 보이면 실패.
9. 실사용 테스트 **1920×1080 / 1600×900 / 1366×768**, 버튼 클릭 가능한 크기, 메뉴 클릭/게임 플레이 방해 여부 확인.
10. **이미지 하나라도 실제 Unity 연결 위치가 없으면 납품 목록에서 제거**한다. 완성 여부는 그림 수가 아니라 게임에서 제대로 쓰이는지로 판단한다.

### 제작 순서

1. **공통 패널 `UI_Panel.png` 1장**을 먼저 만들어 대화창·안내창·결과창에 모두 적용되는지 확인.
2. **공통 버튼 `UI_Button.png` 1장**을 만들어 다양한 폭·클릭 상태에서 테스트.
3. **마우스 모드 안정화 `Stability_Frame/Track/Fill.png` 3장**을 각각 내보내고 실제 안정화 값에 연결.
4. 기존 재킷 2개 검수 → 필요한 곡 재킷만 추가 제작 → 각 차트 Sprite 슬롯에 연결.

**코어 신규 UI는 5개 PNG.** 불필요한 장식용 PNG와 신규 노트 PNG는 **0개**. 곡 재킷은 기존 이미지의 적합성 확인 후 별도로 결정한다.
