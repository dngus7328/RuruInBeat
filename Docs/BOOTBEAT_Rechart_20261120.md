# 《시작의 박동》 (BOOTBEAT) — Lv.6 채보/탄막 재작업

## 목표
- **피노 이동 = 마우스 이동으로 탄막 회피**. 이동 영역은 기존 의도대로 하단을 유지.
- **리듬 입력 = 좌클릭/우클릭/휠, 노트 위치 클릭 불필요**. 기존 판정 시간, 오디오, 접근 원의 역할과 감소 시간 유지.
- 곡을 단순히 정박으로 따라가는 대신, **정박 → 엇박/응답 → 짧은 연타/동시 입력 → 휠 → 숨 고르기**를 반복하며 점진적으로 강화.
- 탄막은 무작위 다발 대신 **보이는 적의 발사 예고 → 구별되는 회피 패턴 → 다음 동작을 예측 가능한 길**로 구성.

## 오디오에서 실제로 확인한 자료
- 원본 `Assets/Song/BOOTBEAT.wav`의 재생 길이: **128.6초**.
- 채보 BPM은 **134.27** 그대로 유지. 실제 음원의 16비트 스펙트럼 변화에서 타격 후보 **718개**를 추출했으며, 모든 후보를 노트로 옮기지 않고 강세/프레이즈에 필요한 타격만 선택함.
- 오디오 분석은 `Tools/ChartRework/bootbeat_audio_profile.py`와 `.github/workflows/bootbeat-audio-profile.yml`에서 재현 가능. 자극적인 스펙트럼 변화가 반드시 킥/보컬/정확한 박자를 뜻하지는 않으므로 곡 구간별 손맛을 고려한 재구성에 보조 자료로만 사용함.

## 곡의 흐름
- **0~14초 / 0~32박:** 좌우 입력의 기본 박동을 먼저 알려주고, 2박 반복에 엇박 응답을 넣음. 탄막은 한꺼번에 덮지 않는 짧은 맥박/좌우 응답 패턴.
- **14~36초 / 32~80박:** 같은 리듬 구절을 변형해 4박의 정박·엇박을 섞음. 두 칸이 열린 이동 회피문과 짧은 빗방울 패턴으로 회피 방향을 배우게 함.
- **36~57초 / 80~128박:** 짧은 연타/휠/동시 입력을 교대하고 패턴의 박자 속도 변화로 긴장을 쌓음.
- **57~79초 / 128~176박:** 반복 모티프에 역방향 응답을 더한 뒤, 중간 숨 고르기 구간을 둠.
- **79~100초 / 176~224박:** 4박 구절에 엇박 강조와 짧은 반복을 더하고 이동 회피문을 다시 변주.
- **100~114초 / 224~256박:** 음원 에너지가 높은 구간. 짧은 5타 리듬 구절과 이동 회피문/엇박 탄막/한 번의 원형 폭발을 결합하되, 휠의 필수 입력 중에는 일반 노트가 강제되지 않도록 설계.
- **114초 이후 / 256~288박:** 밀도와 공격 빈도를 다시 낮춰 음악의 마무리에 맞춤.

## 채보 아트 디렉션
- 입력 위치를 강제하지 않으며 **L/R/휠 식별 + 박자 읽기**가 제일 중요.
- 노트 본체의 위치가 겹치거나 판정 순서가 숨겨지는 패턴은 정리.
- 접근 원은 **그 노트의 판정 순간에 본체 크기로 맞닿는 타이밍 가이드**, 별도의 공격 오브젝트나 필수 포인터 위치가 아님.
- `PinoMoveArea`는 건드리지 않음.
- 다른 5곡 및 BOOTBEAT 숨김 Lv.11 차트는 수정하지 않음.

## 확인 방법
1. GitHub Desktop에서 테스트 브랜치를 체크아웃하거나 PR 병합 후 최신 커밋을 받기.
2. Unity `Assets/Scene/SongSelectScene.unity`에서 BOOTBEAT (Lv.6) 선택.
3. 인트로에서 L/R 읽기 → 20초 무렵의 방어 패턴 → 100~114초의 고조 구간 → 곡 종료 결과창을 연이어 확인.
4. 특히 곡의 **소리와 판정 일치, 적 등장/발사 퇴장, 안전 통로 실제 폭, 노트와 탄막이 겹치는 실제 화면**을 평가.

이 변경의 검증 결과는 Unity Editor 컴파일 및 자동 테스트와 실제 플레이 확인을 구분한다. 플레이 반응을 보고 노트 수·탄속·회피문 폭을 다시 조절할 수 있도록 모든 변경은 GitHub의 별도 브랜치/커밋에 보존됨.
