# 루루 인 비트 — 게임 기획 이전 요약
> 최신 기준은 [통합 제작 명세서](MASTER_PRODUCTION_SPEC_20261128.md)이다. 이 문서는 이전 기획의 요약으로 유지하며 독립적인 우선권을 갖지 않는다. 현재 작업 범위는 게임 기획이며 이미지·UI·리소스 제작 및 Unity 적용은 보류한다.

## 1. 프로젝트 개요
- 제목: 루루 인 비트 (Ruru In Beat)
- 플랫폼: PC, Unity, 1920×1080 기준.
- 장르: 일본 서브컬처풍 인디 리듬 액션 × 탄막 회피.
- 핵심 경험: 음악의 리듬에 맞춰 마우스를 입력하면서 피노를 이동시켜 탄막을 회피한다.
- 세계관: 게임기 내부 세계를 배경으로 루루와 복구 요정 피노의 이야기를 전개한다. 세부 스토리와 대사는 기존 데이터를 유지한다.
- 게임기 콘셉트는 실제 기기 외형이 아니라 선택·입력 반응, 상태 표시, 화면 전환에 반영한다.

## 2. 핵심 플레이
| 조작 | 기능 |
|---|---|
| 마우스 이동 | 피노 이동 및 탄막 회피 |
| 좌클릭 | 좌클릭 리듬 입력 |
| 우클릭 | 우클릭 리듬 입력 |
| 휠 | 휠 리듬 입력 |
| ESC | 일시정지 |

기본 잠금 모드에서 입력 종류와 타이밍을 판정한다. 리듬 입력과 이동·회피를 함께 수행한다. 채보와 탄막은 실제 음원의 악센트 및 구절에 맞춰 설계한다. 기존 판정 수치, 노트 시스템, 게임판 및 탄막 구현은 별도 승인 없이 변경하지 않는다. 과거 키보드 4키 플레이 방식은 현행 기획에 포함하지 않는다.

## 3. 판정·점수·안정화
- PERFECT / GREAT / GOOD / MISS 판정 및 콤보 기록.
- 100만 점 체계.
- 안정화는 판정 및 피격에 따라 변하며 0이면 실패한다.
- 곡별 최고 기록과 결과 랭크를 표시한다.
- 세부 판정 시간, 점수 배분, 랭크 경계, 안정화 증감 수치는 기존 구현을 기준으로 유지하며 본 문서에서 임의 확정하지 않는다.

## 4. 전체 화면 흐름
실행 → 인트로 → 타이틀 → 메인 메뉴 → 최초 스토리·튜토리얼 또는 곡 선택 → 로딩 → READY / 3·2·1 / GO → 플레이 → 결과 → 재도전 또는 곡 선택.

설정·크레딧·종료 확인 및 일시정지·재개 흐름을 지원한다.

## 5. 화면별 기능 요구사항
### 5.1 인트로·타이틀
인트로 이후 타이틀을 표시한다. 타이틀은 로고, 일러스트, 작은 CLICK TO START로 구성하며 클릭·키보드·터치 입력으로 메인 메뉴에 진입한다. 터치 진입 지원은 모바일 플레이 지원을 의미하지 않는다.

### 5.2 메인 메뉴
타이틀과 분리된 화면으로 플레이·설정·종료를 제공한다. 크레딧은 하단 보조 메뉴로 배치한다. 플레이 선택 후 최초 스토리·튜토리얼 또는 곡 선택으로 이동한다. 종료는 확인 절차를 제공한다.

### 5.3 스토리·튜토리얼
기존 스토리 데이터를 사용한다. 튜토리얼은 시작 선택 이후 진행하며 다시하기를 지원한다.
1. 피노 이동
2. 좌클릭
3. 우클릭
4. 휠
5. 탄막 회피
6. 종합 실습

대화와 실제 조작 안내를 중심으로 구성하고 실습 중 피노·노트·탄막을 가리지 않는다.

### 5.4 곡 선택
재킷, 상세 정보, 검색, 정렬, 분류, 최고 기록, 자동 미리듣기, 플레이를 제공한다. 미리듣기 전용 버튼은 신규 제작하지 않는다. 곡당 단일 채보이며 별도의 난이도 선택 기능을 추가하지 않는다. PC 마우스 조작에 적합한 정보 계층과 선택 상태를 갖춘다.

### 5.5 로딩·시작
로딩 화면은 필수 정보만 표시한다. 플레이 시작 전에 READY / 3·2·1 / GO를 표시한다. 동적 문자는 런타임에서 처리한다.

### 5.6 인게임
기존 게임판, 노트, 탄막을 유지한다. 신규 그래픽 설계 범위는 상단 HUD로 제한한다.

HUD 표시 항목은 재킷, 곡명, 안정화, 콤보, 점수의 다섯 가지다. 진행바, 시간, 안정화 퍼센트, 상시 일시정지 버튼은 표시하지 않는다.

안정화 게이지: 외곽 640×28px, 내부 628×20px, 사선 9개로 10구간 구성. 흰색 채움은 Unity에서 상태별 색상으로 변경한다. 프레임·트랙·채움·분할선은 기능에 맞게 분리한다. 숫자나 문자로 안정화 값을 추가 표시하지 않는다.

### 5.7 일시정지
ESC로 진입하며 계속, 재시작, 곡 선택을 제공한다. 계속 선택 시 재개 카운트다운을 거친다.

### 5.8 결과
클리어/실패, 곡명, 최종 점수, 랭크, PERFECT/GREAT/GOOD/MISS 통계, 콤보, 최고 기록, 피노 반응을 표시한다. 점수와 랭크를 주요 정보로 구성한다. 재도전과 곡 선택을 제공한다.

### 5.9 설정·크레딧·종료 확인
설정 카테고리는 사운드/게임/화면/조작/기타로 구성한다. 라벨과 조작 부품을 정렬하고 기존 설정 기능을 보존한다. 세부 설정 항목 및 기본값은 기존 구현과 대조하며 임의 추가하지 않는다. 크레딧과 종료 확인을 지원한다.

## 6. 데모 수록 범위
튜토리얼 별도, 데모 수록곡 6곡. 6곡 전부를 클리어해도 엔딩이 발생하지 않는다.
- BOOTBEAT
- Cotton Pulse
- Pop'n Dash
- Oddbeat Shuffle
- 瞬奏 -SHUNSOU-
- Full-Band Hit

각 곡은 단일 채보를 사용한다.

## 7. UI·그래픽 제작 연계
[통합 제작 명세서 §22](MASTER_PRODUCTION_SPEC_20261128.md#22-최신-시각-방향-확정--라벤더-아케이드-시안-2026-11-28)를 시각 제작의 기준으로 사용한다. 현재 아트 제작은 보류한다.
- 경계가 명확한 불투명 단색 면, 넓은 여백, 절제된 그래픽. 색과 형태로 정보 및 선택 상태 구분.
- 실제 게임기 본체, 반복되는 장식, 과도한 네온·글로우·금속·그라데이션, 모바일식 대형 버튼 및 카드 반복을 피한다.
- 사용자가 선호한 라벤더 아케이드 시안의 분위기를 유지한다. 확정 루루·피노 원본의 외형·그림체·의상·비율은 보존하며 장면별 구도·포즈·연출만 재구성할 수 있다.
- 1920×1080 기준 일반 버튼 높이 40~48px, 주요 버튼 48~64px, 일반 글자 20~24px, 보조 글자 16~18px 권장. 확정 규격이 아니며 필요한 곳만 1~2px 선을 사용한다.
- CHUNITHM의 게이지, DJMAX RESPECT V의 PC 목록·결과, Muse Dash의 캐릭터와 UI, UNBEATABLE의 편집 디자인을 실제 화면으로 조사하되 외형을 복제하지 않는다.
- 한 화면씩 충분한 해상도로 디자인·검수한 뒤 기능별 부품으로 분리한다. 투명 PNG, 배경·캐릭터·로고·UI 독립, 동적 글자·숫자는 TMP Paperlogy 7Bold.
- 기존 자산은 품질과 필요에 따라 유지 또는 교체한다. 과거 개별 부품 작업을 우선순위로 강제하지 않는다.

## 8. 검수 및 완료 기준
- 타이틀 진입 입력과 별도 메인 메뉴의 정상 전환.
- 최초 튜토리얼 및 다시하기, 여섯 단계 조작 안내와 실제 판정.
- 여섯 곡의 선택·검색·정렬·분류·미리듣기·플레이 및 기록 표시.
- 로딩과 시작 카운트다운, 마우스 입력 및 회피, 판정·점수·안정화 표시와 실패 처리.
- ESC 일시정지, 재개 카운트다운, 재시작·곡 선택.
- 결과 데이터 표시, 재도전·곡 선택, 설정·크레딧·종료 확인.
- 실제 Unity 화면에서 가독성, 조작 가능 여부, 이미지 연결 및 플레이 시인성 검수.

위 항목은 검수 요구사항이며 통과 기록이 아니다. 타이틀 신규 입력 및 메뉴 분리는 기존 문서상 구현 목표다. 본 문서 갱신에서는 Unity 실행 검증을 수행하지 않았다. 실제 구현 및 실행 검증 전 완료를 주장하지 않는다.
