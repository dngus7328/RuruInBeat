# 루루 인 비트 — 통합 게임 기획·아트·UI 제작 명세
2026-11-28 | PC 인디게임 | 제작 요구사항 기준서

**현재 작업 범위: 게임 기획 확정. 신규 이미지·UI·일러스트·리소스 제작 및 Unity 적용은 사용자 지시에 따라 보류.** 시각 방향은 §22(라벤더 아케이드 시안), 차트 카탈로그 감사 보완은 §23을 참조한다.

> 이 문서는 게임과 그래픽을 제작할 때 적용할 기준이다. Unity 구현 완료, 아트 완성 또는 검수 합격을 선언하는 문서가 아니다. 이전 GAME_DESIGN_CURRENT.md, ART_DIRECTION_CURRENT.md, 화면 도면 및 개별 작업표와 충돌할 경우 이 문서의 최신 사용자 결정이 우선한다. 기존 문서는 이력으로 보존한다.

## 1. 작품의 정의
- 제목: 루루 인 비트 (Ruru In Beat). Unity 기반 PC 전용 리듬 액션 × 탄막 회피 인디게임. 기준 해상도 1920×1080.
- 루루는 현실에서 리듬게임을 즐기는 소녀이며, 피노는 게임 내부의 이상 현상을 처리하는 요정이다. 두 인물은 처음부터 아는 사이가 아니라 게임 실행 중 처음 만난다. 루루가 가상세계로 직접 들어간다는 설정은 추가하지 않는다. 바이러스 침입을 계기로 피노가 게임 플레이를 방해하는 이상 현상에 대응한다. 기존 세계관과 캐릭터를 유지한다.
- 작품의 필수 감성: 경쾌함, 세련됨, 캐릭터성, 장난스러움, 실험적 표현.
- 목표 경험: 음악적 쾌감, 복합 조작의 성취감, 피지컬과 숙련도, 패턴 공략, 시청각적 몰입, 캐릭터와의 교감.
- 시각 정체성: 아케이드 인터페이스, 일본 서브컬처, 디지털 팝, 실험적 그래픽 디자인. 특히 곡 선택은 게임 패키지를 고르는 경험.
- 독립 인디게임의 작가성과 규모에 적합한 구성. 대형 게임 외형을 복제하거나 콘텐츠·기능 수를 늘려 품질을 가장하지 않는다.

- 기획·그래픽 검토 중에는 씬·스크립트·프리팹·리소스를 직접 수정하지 않는다. 승인된 디자인을 구현할 때 기존 연결과 데이터를 보존한다.
- 4키 레인, 키 캡, 별도 전면 게임판 및 폐기된 키보드 플레이 체계는 신규 제작하거나 복원하지 않는다. 현행 마우스 플레이에 필요한 기존 오브젝트는 유지한다.

## 3. 게임 시스템과 콘텐츠
마우스 이동으로 피노를 이동·회피시키고, L/R/W 리듬 입력을 기존 방식으로 판정한다. ESC 일시정지와 포커스 상실 처리를 유지한다. 타이밍, 노트 접근 방식, 휠 경로, 공격 패턴, 이동 및 피격 판정은 현행 코드·데이터가 기준이다.
- PERFECT/GREAT/GOOD/MISS, 최대 콤보, 정확도, 피격, 그레이즈, 헛클릭 및 최고 기록을 실제 기록에서 읽는다.
- 100만 점 만점. 안정화 소진 또는 600,000점 미만은 실패. SS=1,000,000, S≥900,000, A≥800,000, B≥700,000, C≥600,000, 실패 표시 F. 실패한 기록을 클리어로 저장하지 않는다. 근거: Assets/Scripts/MousePlay/MouseModeResultFlow.cs.
- 음악의 프레이즈, 악센트, 지속음, 휴지와 노트의 관계를 귀로 검수한다. 단순한 정박 나열, 밀도·속도 증가만으로 난이도를 올리는 것, 회피 불가능한 필수 입력, 운에 의존하는 공격은 불합격이다.
- 현행 곡별 차트와 공격 이벤트를 기본값으로 보존한다. 개선이 필요한 구간은 음원 시간·실제 플레이 증거·영향 범위를 명시한다. 자동 음향 분석은 보조 증거이며 실제 청취와 플레이를 대체할 수 없다.
- 제작 순서: 음악 → 채보 → 음악·채보에 대응하는 바이러스와 탄막 → 배경·연출. 사용자가 직접 편집하는 채보는 편집기에서 음악과 타격음을 함께 확인하며 쉽게 수정할 수 있어야 한다. 탄막은 채보의 요구 동작과 음악에 맞추어 설계자가 제작하되 사용자가 수정할 수 있도록 기존 Inspector 및 편집 데이터의 접근성을 유지한다. UI 역시 향후 Inspector에서 교체·수정 가능하게 관리한다. 이를 이유로 현재 정상 편집기나 Unity 파일을 재작성하지 않는다.

### 3.1 데모 범위
튜토리얼 별도 + 데모판 일반 수록곡 6곡, 곡당 단일 채보. 이 6곡은 데모 버전의 수록 범위일 뿐, 전체 이야기의 완결 조건이 아니다. 여섯 곡을 모두 플레이하거나 클리어해도 엔딩은 발생하지 않는다. 6곡 완주를 조건으로 최종 보스, 엔딩, 엔딩 크레딧을 신규 제작하거나 추가하지 않는다. 기존 결과 화면과 곡 선택 흐름을 유지한다. 기존 곡 데이터의 제목·아티스트·레벨·BPM 및 길이를 그대로 읽는다. 아래는 신규 차트 지시가 아닌 곡별 검수 초점이다.

| 곡/식별자 | 플레이 검수 | 아트 검수 |
|---|---|---|
| 시작의 박동 / BOOTBEAT | 기본 박자, 네 휠 프레이즈, 첫 학습 곡의 회피 여유 | 기존 반복 모티프와 노트 접근 원을 구별 |
| 솜결의 맥박 / CottonPulse | 지속 구간, 짝을 이루는 입력, 휠 시작·끝 식별 | 밝은 색면 위 휠 경로 대비 |
| 톡톡 튀는 질주 / PopnDash | 튀는 리듬, 짧은 연속 입력, 이동 부담 | 장식이 다음 노트와 경쟁하지 않음 |
| 엇박자의 춤 / OddbeatShuffle | 엇박, 교대 입력과 회피의 결합 | 가장자리 모티프와 공격 예고 구별 |
| 합주의 일격 / FullBandHit | 복합 입력, 긴 휠과 탄막의 동시 가독성 | 조밀한 재킷 요소를 플레이 영역에 반복하지 않음 |
| 찰나의 연주 / SHUNSOU | 빠른 교대 및 지속 구간 대비, 변속 가독성 | 빠른 시선 이동 중 위험 신호 식별 |

참고 이력: SixSong_MouseChart_RhythmRevision_20261125.md 및 기존 차트 검수 문서. 여섯 곡의 실제 Unity 플레이 합격은 별도 증빙이 필요하다.

## 4. 화면 흐름
실행 → 모니터 개방/타이틀 → 화면 클릭 → 메인 메뉴 → 최초 스토리·튜토리얼 또는 곡 선택 → 로딩 → 모니터 개방 → READY/3·2·1/GO → 플레이 → 모니터 폐쇄 → 결과 → 재도전/곡 선택.
기존 실행 및 씬 전환 로직을 보존한다. 설정, 크레딧, 종료 확인, 튜토리얼 다시하기, ESC 일시정지, 포커스 상실, 재개 카운트다운을 지원한다. 스토리 연결은 기존 StoryFlowSettings와 TutorialStory 데이터를 따른다.

## 5. 아트 디렉션: 제작 기준
### 5.1 캐릭터
확정 기준: 루루_확정(20261027-004153).png, 피노_확정(1).png. 기존 곡 재킷과 배경 일러스트를 추가 기준으로 사용한다.
- 루루: 약 4.5등신, 나른한 반쯤 감긴 눈, 고리 모양 잔머리, 큰 면으로 갈라지는 짙은 보라색 장발, 내려온 겉옷과 기존 검은 상하의, 고양이 실내화. 의상·장신구·배색·선질을 보존한다.
- 피노: 약 4등신, 짧은 밝은 머리, 뾰족귀, 기존 각진 날개 한 쌍, 긴 소매, 사선 스트랩과 파우치. 손가락은 다섯 개, 소매·날개·손·몸의 앞뒤 관계를 명확하게 그린다.
- 얼굴형, 눈매, 머리 덩어리, 신체 비율, 의상 구조, 장신구, 색, 선 굵기, 1~2단 셀 채색은 일치해야 한다. 캐릭터를 일반적인 AI 애니풍으로 바꾸지 않는다.
- 원본 보존은 원본 포즈 복사가 아니다. 화면별 목적에 맞는 신규 포즈, 표정, 시선, 실루엣, 장면 구성을 설계한다. 기존 컷이 구도와 연기에 맞으면 재사용하고, 맞지 않으면 원본 화풍으로 새로 그린다.
- 동일 컷에서 표정만 바뀌면 얼굴 레이어 교체를 우선 고려한다. 실제 자세가 변하는 경우에만 전체 프레임을 추가한다. 날개/머리카락/소매 모션은 필요한 경우만 분리한다.

### 5.2 그래픽 문법
- 기본은 불투명 색면, 정돈된 문자와 의미 있는 형태. 아케이드 감성은 선택 상태, 조작 응답, 모니터 개폐, 타이밍 표현으로 구현한다. 기계 본체·나사·조이스틱·CRT 테두리를 화면에 그리지 않는다.
- 기존 Ink #241D34, Paper #F1EBF9, Lavender #C0ACE5, Pink #F7A6B7은 참고 기반이며 전 화면을 보라색으로 채우는 강제 팔레트가 아니다. Mint #9DDEC9 / Yellow #F3D18C / Danger #EF7185는 안정화 상태색으로 유지한다. 재킷별 대표색을 사용하되 기능색과 충돌하지 않게 한다.
- 각 화면은 서로 다른 역할의 편집 구도를 가지되 폰트, 선택 피드백, 색의 사용 방식 및 일관된 조형 언어를 공유한다. 모든 화면을 동일한 사각 카드와 절단 모서리로 만들지 않는다.
- 시각적 장식은 일러스트 또는 곡의 실제 모티프와 연결되어야 한다. 의미 없는 사선, 원형 링, 별, 날개, 회로, 과도한 발광·금속광택·홀로그램 금지. 파격적인 비대칭도 정보가 잘 읽힐 때만 허용한다.
- Paperlogy 7Bold / TextMeshPro. 한글·영문·숫자·랭크·판정·카운트다운·메뉴 텍스트는 런타임 처리. 기존 로고와 기존 재킷에 속한 원래 타이포만 이미지에 유지 가능.
- PC 기준 설계 출발 범위: 일반 메뉴 40~48px 높이, 주요 조작 48~64px, 일반 텍스트 20~24px, 보조 16~18px. 실제 1080p에서 읽기와 클릭 가능 여부를 확인하여 조정한다. 과거 임의 좌표/크기나 이 범위만 맞추었다는 이유로 합격시키지 않는다.

## 6. 화면별 디자인·UX·일러스트 요구사항
아래는 화면의 제작 목표와 기능 명세다. 그림이 없는 도형 시안이나 임의 좌표표는 최종 디자인이 아니다. 레이아웃 후보는 실제 원본 및 신규 컷이 들어간 1920×1080 화면으로 검증한다.

### 6.1 타이틀·메인 메뉴
- 첫 상태: 로고와 메인 비주얼 중심. 화면 어디든 클릭하여 진입한다. 작은 클릭 안내는 TMP로 구현한다. 기존 정상 입력 지원은 삭제하지 않는다.
- 클릭 이후 메뉴 선택창과 부유 연출이 함께 시작되도록 구성한다. 메뉴와 일러스트가 하나의 장면처럼 연결되어야 한다. 부유할 대상·진폭·주기는 실제 움직임에 따라 결정하며 클릭 영역은 고정한다. 기존 인트로 로직을 유지한다.
- 게임 시작/설정/종료/크레딧. 메뉴를 화면 너비만큼 큰 버튼으로 만들거나 무조건 왼쪽에 배치하지 않는다. 로고, 얼굴, 손, 날개가 메뉴와 겹치지 않게 한다.
- 원화: 기존 확정 루루 일러스트와 로고를 기준 자산으로 보존한다. 배경·메뉴는 애니메이션 오프닝처럼 통통 튀는 연출로 재구성한다. §22의 따뜻한 게임방 분위기와 편집 그래픽을 유지하되, 방 그림 위에 거대한 메뉴 세 개를 붙이는 구성으로 끝내지 않는다. 신규 포즈가 필요할 경우 확정 캐릭터의 외형·선질을 보존하고 화면에 맞게 구성한다. 피노의 타이틀 등장 자체는 강제하지 않으며, 등장시킬 경우 첫 만남 설정과 충돌하는 친밀한 일상 연출을 스토리 사실로 확정하지 않는다. 로고·배경·인물·메뉴는 독립 레이어로 관리한다.
- 금지: 원본 전신을 그대로 복사해 빈 공간에 붙이기, 실제 게임기 외형, 메뉴보다 큰 장식, 초점 없는 구도.
- 검수: 클릭 연타, 메뉴 진입, 설정·크레딧·종료 취소 복귀, 첫 상태와 메뉴 상태의 조형 및 모션 캡처.

### 6.2 곡 선택
- 6곡을 각각 하나의 게임 패키지로 경험하게 한다. 재킷·제목·아티스트·레벨·BPM·기록은 선택된 곡의 한 편집 단위로 구성하되, 클릭 가능한 영역과 정보 위치는 일관되게 유지한다.
- 배치 후보는 모든 곡의 재킷을 비교 가능한 패키지 진열/탐색 구조와 현재 선택의 확장 표현을 중심으로 검토한다. 기존 거대한 목록과 상세 패널을 그대로 재현하지 않는다. 특정 캐러셀이나 실제 CD/카트리지 형태를 강제하지 않는다.
- 미리듣기 전용 버튼은 배치하지 않는다. 기존 곡 미리듣기 기능은 선택과 함께 자연스럽게 활용하는 방향으로 검토하고 정상 기능을 삭제하지 않는다. 탐색 중 짧은 음원이 계속 중첩되는 문제를 방지한다.
- 현재 곡 검색·정렬·분류가 이미 구현된 경우 기반 기능은 보존한다. 6곡 화면을 상시 조작 부품으로 가득 채우지 않고 보조 노출 또는 통합을 검토한다. 삭제나 기존 반복 클릭 동작 변경은 별도 승인 사항이다.
- 곡마다 기존 재킷 원본과 가로 배경을 유지·검수한다. 필요한 경우 패키지에 맞게 신규 배경 그래픽을 재구성한다. 정사각 재킷을 임의로 늘리거나 가로 배경으로 확대 복제하지 않는다.
- 재킷·선택 강조·상세 정보는 각각 독립. 실제 패키지의 입체 케이스, 두꺼운 베젤, 기계 도킹 장치가 요구되는 것이 아니다.
- 검수: 6곡의 탐색·선택·기록·시작, 기존 조작 방식, 긴 제목, 선택 변경, 미리듣기 전환, 결과 복귀 시 이전 곡 유지. 고정 선택 상태와 Hover가 혼동되지 않아야 한다.

### 6.3 스토리·튜토리얼
- 기존 대화와 단계 데이터 유지: 피노 이동 → 좌클릭 → 우클릭 → 휠 → 탄막 회피 → 종합 실습. 결과 및 재연습·곡 선택 진입은 기존 이수 조건을 따른다.
- 대화에서는 해당 화자의 시선·표정·자세를 중심으로 장면을 연출한다. 큰 대화창은 실습 중 닫는다. 실습 안내는 필요한 한 행동만 보여 주고 노트·탄막·피노의 이동 공간을 침범하지 않는다.
- 조작 그림은 정확히 4가지: 이동, 왼쪽 클릭, 오른쪽 클릭, 휠. 회피는 이동 그림, 종합은 기존 그림을 조합한다. 설정의 조작 안내와 공유한다. 현행 SettingsCategoryController.cs의 Guide_MouseMove / Guide_LeftClick / Guide_RightClick / Guide_Wheel 연결을 우선 검수한다.
- 같은 마우스 실루엣과 선 굵기, 해당 부위의 명확한 강조. 글자는 별도 TMP. 보조 아이콘의 개수를 늘리는 대신 실습 자체로 설명한다.
- 루루의 나른한 말투와 피노의 적극적인 성격을 유지한다. 실패 반응은 짧고 상황에 맞게 하며 연속 출력으로 음악과 조작을 방해하지 않는다.
- 검수: 초심자가 외부 설명 없이 각 조작을 이해하고 종합 실습에 도달. 실패, 재시도, 이수 저장, 다시하기, 일시정지 및 재개 정상.

### 6.4 인게임
- HUD는 곡 재킷·곡 제목·안정화 게이지·콤보·점수 다섯 항목만 상시 표시한다. 상단 배치. 진행바·시간·퍼센트·상태 문구·별도 일시정지 버튼·날개 장식 금지. 점수·콤보는 TMP.
- 거대한 전체 상단 패널 대신 각 정보에 필요한 대비와 정렬로 작고 정밀한 인터페이스를 만든다. 기존 패널이 플레이 영역을 차지한다면 레이아웃을 다시 설계한다.
- 안정화 게이지의 확정 원본 규격: 프레임 640×28, 내부 트랙·백색 채움·분할선 각각 628×20, 좌우 6px·상하 4px, 사선 9개로 10구간. 프레임 중앙 투명, 분할선 외에는 투명, 채움은 왼쪽 기준 Filled Horizontal, 상태색은 런타임 변경. 기존 부품이 맞으면 재사용.
- 0/1/50/100% 및 정상·주의·위험 시 모든 구성 요소가 정확히 표시된다. 상태 임계값은 기존 코드 유지.
- 현행 L/R/W 노트와 접근 원, 휠 경로, 피노, 탄막의 구조는 유지한다. 배경은 조작·판정 정보를 가리지 않도록 명암과 국부 대비를 조정한다. 색만으로 입력 종류를 구별하지 않는다. 공격 예고 영역과 실제 충돌 영역이 일치해야 한다.
- 곡별 배경은 음악 자체를 시각화하는 그래픽을 우선한다. 특정 방이나 도시·건물 같은 장소를 모든 곡에 강제하지 않는다. 기존 곡 배경은 보존하며, 이후 재구성이 필요한 경우 음원의 분위기와 리듬을 먼저 파악하여 소재·색면·선질을 설계한다. 밀집 구간에서 시선을 분산시키는 배경 장식은 제거 또는 약화한다. 현재 이미지 제작은 보류한다.
- 짧고 명확한 타격/피격 반응, 점수·콤보 변화, 음악 악센트에 맞는 배경 효과를 강화하되 판정 타이밍 및 플레이 시인성을 바꾸지 않는다. 반복 섬광·과도한 화면 흔들림 금지.
- 검수: 여섯 곡 모두의 저·고밀도, 휠 경로, 탄막 회피, 배경 밝기, 최대 자릿수, 안정화 실패, 입력 지연과 실제 충돌.

### 6.5 로딩·게임 시작/종료·일시정지
- 현재 사용하는 모니터 개폐 효과를 보존한다. 프로그램 시작·종료 및 곡 시작·종료의 의미 있는 전환에 사용하며 일반 메뉴 이동마다 무분별하게 반복하지 않는다. 정확한 연출 범위와 시간은 기존 SceneLoadingTransition / MouseBootSequenceUI 동작을 기준으로 한다.
- 로딩 완료 후 화면 개방과 카운트다운. READY/3·2·1/GO는 TMP, 기존 애니메이션 재사용. 별도 숫자 이미지, 모니터 테두리, 로딩 전용 대형 판 제작 금지.
- 일시정지는 정지된 플레이 화면을 유지하고 필요한 만큼 명암을 조절한다. 기존 계속하기/다시 도전/곡 선택만 명확히 배치한다. 거대 모달, 전용 캐릭터 장식 불필요.
- MouseRhythmPauseUI의 기본 등장 0.26초/퇴장 0.18초, 12px 이동, 시작 배율 0.96, 재개 단계 0.85초/GO 0.45초 및 포커스 상실 재개 처리 유지. 씬의 직렬화 값이 다르면 실제 씬 값을 우선한다.
- 검수: ESC, 창 포커스, 카운트다운 중 포커스 상실, 입력 중복 차단, 재도전, 곡 선택, 음악·노트·탄막 동기화, 종료 확인.

### 6.6 결과
- 실제 플레이 기록의 성취감을 주는 화면. 거대한 통계 카드와 캐릭터를 기계적으로 좌우로 나눈 구조, 또는 숫자만 확대하고 사선을 깐 와이어프레임은 불합격이다.
- 원화와 점수·랭크의 조형 관계를 먼저 설계한다. 피노의 몸짓/시선과 점수의 위치, 표정과 결과 상태, 대사의 위치가 유기적으로 연결되어야 한다. 일러스트를 빈 칸에 나중에 붙이지 않는다.
- 기존 클리어/실패용 피노 4프레임씩(OriginalParts/Characters/Pino_Clear_0~3, Pino_Failed_0~3)과 상황별 루루·피노 대사를 먼저 검수한다. 구도와 연기가 맞지 않으면 기존 화풍으로 새 자세/표정을 제작한다. 신기록은 별도 전신 스프라이트 강제가 아니라 반응과 연출로 차이를 표현한다.
- 정보: 곡명, CLEAR/FAILED/NEW RECORD!, 최종 점수, 랭크, PERFECT/GREAT/GOOD/MISS, MAX COMBO, 피격, 그레이즈, 헛클릭, 정확도, 최고 기록, 플레이 시간, 캐릭터 반응. 기존 점수 표시 게이지와 기능도 보존한다. 재도전·곡 선택.
- 점수와 랭크는 최우선, 판정 및 세부 통계는 일관된 글자 정렬로 비교 가능하게 한다. 프레임·배지·아이콘은 실제 필요한 경우만. 랭크 문자 6종을 그림으로 제작하지 않고 TMP로 표시한다.
- 모니터 폐쇄 이후 결과 표시. 연출이 결과 확인과 재도전을 지연시키지 않는다.
- 검수: 클리어/신기록/점수 미달/안정화 소진, SS~F, 1,000,000점, 통계 일치, 기존 저장 정책, 피노 프레임, 재도전과 곡 선택.

### 6.7 설정·확인창·크레딧
- 현행 사운드/게임/화면/조작/기타 카테고리와 실제 설정 항목 및 동작을 보존한다. 사운드 4종, 노트 속도·타이밍·효과 표시, 화면 모드·해상도·프레임·VSync·밝기, 마우스 조작과 튜토리얼 다시하기, 초기화·크레딧 등. 새 설정값을 임의로 추가하지 않는다.
- 설정은 실제 설정 항목의 양과 관계에 맞는 단일 구성으로 디자인한다. 항목별 반복 카드, 거대 카테고리 아이콘, 일반 웹 대시보드 형태 금지. 라벨·조작부·현재 값은 고정된 기준선에 정렬. 선택된 카테고리와 Hover를 명확히 구분한다.
- 설정 UI도 작품의 조형·색과 선택 피드백을 사용한다. 단순한 프로그램 환경설정 화면에 보라색만 칠한 형태는 불합격이다.
- 기존 ControlTrack/ControlFill/ControlKnob, 공통 버튼, 조작 안내 4종을 우선 검수·재사용한다. 스크롤바는 내용이 넘치는 경우에만 레일/손잡이 두 부품. 슬라이더와 스크롤바의 서로 다른 용도를 유지한다.
- 종료/초기화 확인창은 공통 팝업과 버튼 활용. 기록 초기화 등 실제 파괴적 작업은 기존 범위를 명시하고 확인/취소를 구분한다.
- 크레딧은 실제 제작자·음악·일러스트·외부 사용 리소스와 라이선스를 확인하여 기록한다. 근거 없는 제작자, 팬게임·비영리 표기 등을 임의로 추가하지 않는다.
- 검수: 모든 탭·값·최소/최대·토글·해상도·저장·재실행·초기화·취소, 기록 보존 범위, 크레딧 실제 정보.

## 11. 화면 조형과 일러스트 연출의 구체 제작안

기존 요구서에 삽입된 루루·피노 원화 및 BOOTBEAT 배경 예시에서 읽히는 선명한 외곽 실루엣, 짙은 먹보라 윤곽, 밝은 내부 면, 1~2단 셀 채색, 대형 머리/날개 형태를 공통 조형으로 사용한다. 기존 원화의 실제 색을 바꾸지 않는다. UI에는 캐릭터의 면 분할 방식만 번역하며 의상 장식이나 날개 아이콘을 복제해 모든 화면에 붙이지 않는다.

### 11.1 공통 시각 시스템
- 편집면: 종이색/먹색과 곡의 원화 대표색을 화면마다 한 가지 주 강조색으로 조합. 보라색은 캐릭터 고유색으로 남기고 배경의 면적을 자동으로 보라색으로 통일하지 않는다.
- 곡 선택에서는 재킷 밖의 색면은 원본 재킷 대표색에서 뽑되 원화와 정보가 경쟁하면 채도·명도 차이를 낮춘다. 선택은 색만으로 알리지 않고 위치 고정·굵기·명확한 표식 중 하나를 함께 사용.
- 계층: 화면 이름 → 선택 콘텐츠 또는 중요한 기록 → 실제 조작 → 보조 정보. 모든 제목·점수·행동에 큰 프레임을 추가하지 않는다. 화면별 메인 시각 요소는 하나만 설정하고 캐릭터와 그 요소가 시선 흐름을 공유한다.
- 텍스트 일반 정보는 20~24px, 보조 16~18px에서 실제 Paperlogy 7Bold의 획·자간을 검수. 수치 정렬은 우측 또는 고정 기준선, 글꼴 숫자 폭 차이로 점수가 흔들리면 TMP 고정폭 태그나 자간 검수. 선택 강조는 글자 크기를 변경해 주변 버튼이 움직이지 않게 한다.
- 명암 기준(제작 검수 목표): 일반 안내와 수치의 배경 대비 4.5:1 이상, 큰 제목과 의미 있는 상태 도형·외곽 3:1 이상. 원화 위 글자는 가장 밝고 어두운 영역 모두에서 검사. 이 수치는 출시된 게임의 측정 결과가 아니라 신규 QA 기준이다.
- 안전 영역 초기 검수: 1080p 가장자리 32px, 화면 전환 후 중요한 문구·컨트롤이 잘리지 않는지 확인. 이 값은 절대 레이아웃 또는 확정 좌표가 아니다. 720p 및 창모드 실측 우선.

## 13. 스토리 및 연출 근거
TutorialStory.asset의 제목은 '게임 속 이상 현상', opening 8줄, closing 2줄, 6단계 chapterNames/Guides/Success/Lead 및 incompleteClosing/checkpointFailure가 존재한다. 새로운 세계관이나 등장인물·설정을 만들 이유가 없다.
- 사건: 루루가 평소와 다른 리듬게임 화면을 발견 → 피노가 바이러스 반응을 알림 → 마우스 움직임과 접근 원의 타이밍을 이해 → L/R/W 및 빨간 공격을 구별 → 실제 연습 → 곡 선택.
- 루루와 피노는 첫 만남부터 관계가 형성된다. 루루는 관찰과 이해, 피노는 안내와 행동을 담당한다. 본편 대화는 캐릭터성과 관계를 충분히 드러낼 분량을 확보하며, 실습 중 조작 안내만 짧고 명확하게 한다. 기존 TutorialStory의 친숙한 말투 및 이름을 부르는 대사는 첫 만남 설정과의 정합성을 차후 대사 편집 단계에서 확인한다. 개그와 가벼운 관계 중심의 전개를 유지하며 6곡 완주를 이야기의 완결로 취급하지 않는다.
- 각 대화에서 leftPortrait/rightPortrait/background/sound 직접 참조가 0이고 openingBackground도 0이다. 런타임 기본값/폴백의 존재와 실제 표시는 별도 확인한다. 참조가 0이라는 사실만으로 모든 대화 그림이 없다고 단정하지 않는다.
- StoryFlowSettings.asset의 routes는 빈 배열이다. 다른 기본 흐름의 존재를 확인하고 필요한 스토리 연결만 채운다. 새 챕터 수를 임의 확정하지 않는다.
- 대사와 연습 안내는 기존 데이터 편집 방식 사용. 인트로를 처음부터 강제로 반복하거나 스토리를 별도 장편 콘텐츠로 확대하지 않는다.

## 14. 오디오 사양과 검수
Assets/Resources/MouseNoteAudioPalette.asset 및 NoteSoundManager.cs 확인. 총 14개 슬롯: Normal 4판정, LongStart 4판정, LongRelease 4판정, holdTick, pinoHit. Assets/Audio에는 대응 WAV 외 Hit_HIT 1.wav가 추가 존재한다. 두 피격음 파일의 실제 연결은 GUID 대조 후 결정.
| 이벤트 | 음원 재사용 기준 | 실제 코드 기본 음량 |
|---|---|---:|
| 일반 입력 판정 | Normal_* 4종 | 0.7 |
| 지속 입력 시작 | Long_Start_* 4종 | 0.7 |
| 지속 입력 종료 | Long_Release_* 4종 | 0.7 |
| 유지 틱 | Hold_TICK | 0.4 |
| 실제 피격 | pinoHit 슬롯 | 0.8 |

실제 파일의 소리, 지속 시간·톤 및 W 노트 호출 매핑은 청취·이벤트 추적으로 확인한다. 위 슬롯 이름만으로 현재 W 노트가 정확히 어떤 음을 쓰는지 단정하지 않는다.
- NoteSoundManager는 Mouse/Tutorial/Mouse_ 씬에서 오디오 관리자 보장, 2D AudioSource/PlayOneShot을 사용. master×hitSoundVolume, 피격은 master×sfxVolume. Inspector override가 우선. 별도 관리자 중복 생성, 이중 재생, 오프셋 보정과 음악시간 분리를 검수.
- 청취 목표: PERFECT/GREAT/GOOD/MISS와 피격이 소리만으로 구별되되 음악 악센트를 덮지 않는다. 연속 휠 틱이 지나치게 커지거나 음원 종료 후 계속 재생되지 않음. 노트 성공음은 실제 판정 사건에서 1회, 피격음은 실제 피격에서만 1회.
- 메뉴음은 실제 현재 자산을 검수 후 필요 시 선택·확정·취소를 구분하는 최소 3역할로 공유. 새 효과음 파일 3개를 무조건 요구하는 것은 아니다.
- 자동 미리듣기는 기존 설정을 보존한다. 곡 전환/창 전환/시작/재도전 중 두 곡 동시 재생과 불필요한 재생성 금지. 수동 미리듣기 전용 버튼을 다시 만들지 않는다.
- 음량 검수는 0/50/100%, 모든 조합, 빠른 연속 입력, 일시정지·재개. 최종 혼합 신호 clipping 0건을 계측 목표로 한다. 정확한 LUFS 목표는 원본 음원 청취와 레벨 측정 후 결정하며 임의로 마스터링하지 않는다.

### 22.4 일러스트 제작과 동일성 통제
1. 캐릭터 참조는 확정 원본, 분위기 참조는 위 일곱 화면 이미지로 역할을 분리한다. 분위기 시안의 피노나 루루를 캐릭터 원본으로 승격하지 않는다.
2. 새 포즈는 §11.2를 출발점으로 하되 얼굴형·눈매·머리색·의상·날개 수·손가락 수·신체 비례를 원본과 비교한다. 루루를 은발 토끼귀/고양이귀 소녀로 바꾸거나 피노를 동물형 마스코트로 대체하는 결과는 자동 불합격.
3. 배경과 캐릭터는 화면 용도에 맞춰 새로 구도를 짠다. 따뜻한 게임방의 분위기를 유지하면서 곡 배경은 각 곡의 기존 그림과 음악에 맞춰 개별 구성한다. 모든 장면을 같은 게임방에 배치하지 않는다.
4. 다음 이미지 제작에서 한번에 일곱 화면을 합친 콜라주는 분위기 비교용으로만 사용한다. 실제 레이아웃은 화면별 1920×1080, 실제 텍스트/숫자/재킷은 Unity 데이터로 합성하며, 제작용 부품은 별도 PNG.
5. 후속 수정은 승인된 분위기에서 필요한 부분만 교정한다. 색감·원화·조형·기능을 동시에 임의 변경한 대체 디자인을 여러 장 연속 생성하지 않는다.
6. 완성 이미지 검수 시 동일성, 화면 기능, 색채, 조형, 실제 해상도 및 레이어 분리 모두 통과해야 한다. 배경의 분위기만 좋다는 이유로 캐릭터 및 UI 기능 오류를 허용하지 않는다.

### 22.5 리소스 재사용의 추가 확정
프로젝트 첨부 'UI 부품 분리 작업.txt'에 명시된 내용:
- 초기화 버튼은 신규 제작하지 않고 기존 버튼 이미지 재사용.
- 스크롤바는 슬라이더와 별개로 트랙 1개, 스크롤 핸들 1개. 설정 항목이 실제로 넘칠 경우 사용.
- 스크롤바 외곽이나 버튼 장식을 별도 다수 생성하지 않음. 공통 버튼의 현재 상태 표현을 그대로 적용한다.
§7 및 §11에서 중복 제작 가능성으로 기술한 부분은 이 규칙을 우선한다.

### 24.1 제작자의 판단 범위
- 이미 확정된 세계관·조작·데모 수록 범위·시각 분위기를 다시 결정 대상으로 제시하지 않는다. 과거 요구와 최신 요구가 다르면 최신 사용자 결정만 적용하고, 기존 문구를 해당 위치에서 정정한다.
- 사용자가 정할 것은 작품의 방향, 게임 규칙 및 콘텐츠 범위의 중요한 변경이다. 그 외 세부 조형·편집·리소스 조합·오류 발견 및 검수는 제작자가 책임지고 처리한다. 사용자가 매 항목의 누락을 찾아 주어야 진행되는 방식은 금지한다.
- 이미지 제작 재개 시에는 §22의 승인 분위기와 확정 캐릭터 원본을 고정 참조한다. 사용자가 제시한 20261128-143932 타이틀 이미지의 왼쪽 대형 버튼 세 개와 방 일러스트 중심 구성은 최종 디자인 기준으로 사용하지 않는다. 색감·따뜻한 실내 표현만 제한적으로 참고 가능. 다른 캐릭터나 콘솔 외곽을 새로 생성하는 방식으로 대체하지 않는다.
- 검증할 수 없는 사항은 명확히 남기되 계획서, 시안, 제작용 부품, 실제 실행 결과의 완료 상태를 서로 혼동하지 않는다. 사용자의 추가 피드백 없이 처리 가능한 기획 보완은 직접 수행한다.
