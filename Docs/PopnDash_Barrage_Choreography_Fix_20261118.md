# Pop'n Dash 탄막 구조 재설계 — 2026-11-18

## 왜 이전 수정이 체감되지 않았나

- `Mouse.unity`에서 `projectileEmitter`는 `fileID: 0`. 해당 씬에는 `VirusRoot`도 없었다.
- `CreateSourceIndicator`와 `UpdateSourceIndicator`가 실행 경로에서 빠져, 탄환이 허공에서 생성되는 것처럼 보였다.
- 탄막의 실제 위험 도달 시각이 채보 공격 박자보다 수 박 뒤에 있었다. 기존 `pop_*` 구현은 `attack.beat`를 발사 순간으로 사용하여, 피노 높이에 도달하는 시점이 음악 강세와 달랐다.
- 기존 9종은 일부 패턴에서 수십 발씩 넓은 각도로 생성되었고, 테스트용 레이저·폭발·낙하탄 3개가 초반에 추가로 겹쳐 있었다.

## 수정 범위

- Pop'n Dash 전용 `pop_twinfan / pop_echo / pop_pendulum / pop_ribbon / pop_gate / pop_pinwheel / pop_aim / pop_pulse / pop_seedflower` **9종을 재구성**. 한 발사원(.5,.08)에서 시작하는 8~18발 규모의 명확한 음악적 반복/좌우 응답/회피 통로 구조.
- 해당 9종 한 이벤트의 생성 수: 각각 **12 / 9 / 8 / 9 / 18 / 16 / 9 / 16 / 10**. 불필요한 전방위 난사를 줄이되 각 패턴의 개성은 유지.
- 피노 회피 영역 내 기준 높이(PlayArea 상단 기준 `y=.72`)에 일반탄이 **발사 후 4박**에 도달하도록 각도별 속도 보정. 씨앗 분열 자탄은 분열 후 **2박**에 도달. 음악의 원래 공격 강세를 보존하도록 19개 공격 이벤트를 **4박 앞당겨 발사 예약**.
- 실제 바이러스 이미지/발사원 참조가 존재하면 그 위치를 사용. 현재처럼 없는 씬에서는 상단에 **무광 발사구를 실제 생성하여 표시**하고 음악 박자에 맞춰 발광 없이 크기/색 반응. 씨앗 분열 자탄은 별도 발사원처럼 표시하지 않음.
- 초반의 테스트용 `laser / burst / rain` 3개를 Pop'n Dash 활성 채보에서 제거. 다른 곡의 기존 `laser / burst / rain` 처리 코드는 유지.
- `PopnDash_119_REBUILT.json`과 실제 씬에서 재생하는 `NewMouseChart 2.asset`의 공격 이벤트를 동일하게 수정. 노트 200개, BPM 119.26, 노트 판정 시각/위치/종류는 변경하지 않음.

## 정적 검사

- 두 채보 파일의 `pop_*` 공격 이벤트 **19개, 각 패턴 ID 및 박자 일치**; 활성 `Mouse.unity`가 참조하는 차트 GUID 유지.
- C# 스크립트의 괄호 균형과 새 이름 중복, 실제 발사원/이동 좌표 참조를 확인.
- 900×450 가상 화면, 피노 기준 `y=.72`, 약 32px의 가로 위험 영역을 고려해 탄막 궤적 샘플링. 9종 각각의 **가장 좁은 연속 회피 폭 약 118px 이상** (개별 패턴에 대한 정적 추정).
- 게임 실기에서 공격 중첩·피노 이동·UI 가림·입력/오디오 레이턴시를 통합 검증한 것은 아니다. **Unity 컴파일/실제 플레이 테스트는 아직 시행할 수 없음.** 문제가 나타나면 플레이 영상/Unity Console을 기준으로 조정.
