# 마우스 채보 — 구간별 BPM / 템포맵 (검증용 초안)

## 배경
새 Suno 음원의 반복 리듬 간격이 일정하지 않은 구간이 있어, 단일 BPM으로만 표시하던 파형/박자선/판정/탄막 시간이 서로 어긋날 수 있다.

## 적용 방식
- 기존 `bpm`은 **0박 시작 BPM**, `beatZeroSeconds`는 시작 오프셋으로 유지한다.
- 새로운 `tempoChanges`: `[{ "beat": 64, "bpm": 127.2 }, ...]` 형태. 각각 **해당 beat에서 시작하는 BPM**.
- 변경점이 없는 기존 JSON 및 .asset: 예전처럼 단일 BPM으로 작동한다.
- 노트의 `beat` / 휠 `endBeat` / 공격의 `beat`는 공통 `BeatToSeconds` 함수에서 변환한다.
- 에디터 미리듣기 현재 박자, 파형 수평 위치, 노트 재생 미리보기, 곡 끝 계산에도 동일한 tempo map을 적용한다.
- 에디터 `1. 곡 정보` 아래 **구간별 BPM 변경** 섹션에서 현재 박자에 마커 추가 / BPM 조정 / 삭제 가능. 노란 세로선으로 BPM 변경 지점 표시.
- 탄막의 기본 이벤트/낙하탄 예고/충돌 시각도 구간별 실제 시간에 맞춰 변환한다.

## 기존 채보를 편집할 때 주의
- BPM 마커를 추가하거나 이동하면 그 이후 beat의 **실제 재생 초**가 변경된다. 채보의 beat 값 자체는 자동 수정하지 않는다. 파형과 귀로 다시 맞추어야 한다.
- BPM 변경 지점과 겹치는 레이저/폭발탄 이동 궤적은 물리적 속도가 일률적이지 않을 수 있어 Unity 플레이 검수가 필요하다.
- 생성형 음악은 정확한 프로젝트 BPM 메타데이터가 없을 수 있다. 분석으로 얻은 BPM을 사용하되, 비트/초 대응을 확인하고 확정해야 한다.
- Unity 실제 컴파일·실행은 수행하지 않았다. **검증용 Draft PR, main 미병합**.

## 데이터 예시
```json
{
  "bpm": 126.0,
  "beatZeroSeconds": 0.125,
  "tempoChanges": [
    { "beat": 64.0, "bpm": 127.0 },
    { "beat": 128.0, "bpm": 129.2 }
  ]
}
```

## 검수 순서
1. 기존 채보 중 하나를 복제해 tempoChanges 없는 상태로 기존 타이밍이 동일한지 확인.
2. 테스트 채보 BPM=120, 8박에서 180으로 변경. 8박 시각=4초, 12박 시각=5.3333초를 확인.
3. 미리듣기 커서, 파형, 노트 타격, Wheel 종료, 공격 첫 진입이 동일한 시간표에서 움직이는지 확인.
4. 악기별 채보 패턴을 독립적으로 설계한 뒤, 모든 노트·탄막 교차에 대해 실제 마우스 동선 테스트.
