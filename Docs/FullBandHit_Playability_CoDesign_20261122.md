# Full-Band Hit — 클릭 리듬 × 피노 회피 통합 설계 검토 (1차)
검토일: 2026-11-22  
기준: `main` / `Assets/Editor/FullBandHit_MOUSE.json` + `Assets/MouseMode/ChartSystem/Charts/FullBandHit_MOUSE.asset`

## 0. 이 문서의 상태

**설계 점검 초안(미검증), 확정 채보 아님.** 실제 WAV 청음·전체 플레이 검증 없이 박자나 탄막을 고쳐 넣는 일을 피한다. 이 문서의 수치는 기존 JSON의 `BeatToSeconds`와 실제 입력 이벤트를 검사한 것으로, 주파수 검출이 음악적 타격 의도를 입증하지는 않는다. 현재 런타임/곡 데이터를 **수정하지 않았다**.

## 1. 반드시 지킬 조작 규칙

- 게임 플레이 중 OS 커서는 잠김(`CursorLockMode.Locked`). 마우스 **이동량**으로 피노를 움직이고, **좌클릭/우클릭/휠**로 노트를 판정한다. 클릭 노트 위치로 마우스 포인터를 옮기는 게임이 아니다.
- 현재 `MouseModeChartPlayer.IsPointerOnNote`는 커서가 잠긴 상태에서 위치 검사를 통과시킨다. 잠금 해제 상태에서는 원형 노트 위치를 검사한다. 과거 인수인계 문서의 “반드시 원 위 클릭” 문구는 기본 플레이를 정확히 설명하지 못한다.
- 노트마다 **해당 소리의 의도된 타격 순간 = 오차 0ms**. 실제 입력 시각 − 노트 hitTime으로 판정한다. 곡 시작 0초가 모든 노트의 타격 시각 0초라는 뜻은 아니다.
- 노트의 화면 위치는 **먼저 읽히는 순서·동시 입력·리듬 그룹 인지**를 위한 것이며 클릭용 커서 이동 거리 제약이 아니다. 탄막을 피하는 데 필요한 것은 피노 이동 경로다.
- 휠 노트는 시작/지속/끝이 있는 별도 조작 부담이므로, 같은 타이밍에 회피 방향 전환을 무작정 겹치지 않는다.

## 2. 현재 데이터 정적 계측

- 총 **470개 노트**: 좌 230, 우 229, 휠 11. 공격 이벤트 **15개**. 레벨 표기 **13**.
- 노트 등장 간격이 **250ms 이하인 연속 구간 272곳**, **150ms 이하 24곳**(동시 판정 포함, 실제 인간 체감 난도와 일치하지는 않음).
- 롤링 1초 창의 피크는 **7노트**(약 94.39s, 97.05s, 121.66s 부근).
- 8초 창별 노트 수: `0–8:27 / 8–16:25 / 16–24:29 / 24–32:25 / 32–40:28 / 40–48:29 / 48–56:26 / 56–64:30 / 64–72:25 / 72–80:29 / 80–88:35 / 88–96:35 / 96–104:36 / 104–112:31 / 112–120:33 / 120–128:26`.
- 위 창은 **기계적 시간 집계 구간**이다. 곡의 실제 인트로·절·후렴 경계라고 확정할 수 없다.

## 4. 설계 결정을 위한 구체적 규칙 (1차 목표, 미확정)

1. **리듬이 우선:** 각 프레이즈에서 어느 타격음을 플레이어가 따라가는지 지정한다. 모든 음향 트랜지언트를 노트로 놓지 않는다. 반복 프레이즈에는 알아볼 수 있는 좌/우 모티프와 변주를 부여한다.
2. **고속 구간의 완급:** 빠른 클릭 구간을 8초 이상 지속할 때에는 의도한 쉬는 박자, 음향 밀도 변화 또는 휠 전환 여부를 청음으로 결정한다. 일괄적인 노트 삭제·추가는 금지한다.
3. **동시 부담은 의도적으로:** 휠 지속 도중 빠른 방향 전환과 닫히는 문형 탄막을 겹치려면, 실제 피노 충돌 크기로 통과할 수 있는 경로가 **최소 하나** 있어야 한다. 없다면 탄막을 고친다.
4. **노트 읽기:** 겹침 0개는 필요조건이지 충분조건이 아니다. 순서·좌우 유형·다음 타격이 시선 이동 없이 구분되도록 좌표 그룹과 접근 원을 검토한다. **클릭 노트의 원 위치까지 커서를 이동시키라고 요구하지 않는다.**
5. **탄막 예고:** 기존 최소 예고(`EnsureTelegraphLead`)가 있다는 이유로 공정하다고 단정하지 않는다. 실제 탄환의 위험 시각 기준으로, 플레이어가 방향과 통로를 인지할 시간이 있는지 본다.
6. **난도 분배:** 노트가 매우 빠른 구간에는 탄막 가독성을 높이고, 클릭이 비는 구간에는 회피의 매력을 살리는 식으로 역할을 교대한다. 무조건 탄환 수를 줄이거나 늘리는 것이 목적은 아니다.
7. **점수와 보상:** GRAZE는 좋은 회피를 보상하되, 위험 회피를 강요하는 빈도 때문에 음악 입력을 포기하게 만들지 않는다.
8. **변경 안전성:** 음원과 일치하는 타격 시각을 이유 없이 변경하지 않는다. 채보를 고칠 때는 편집 JSON과 게임용 Unity `.asset`을 항상 함께 동기화한다.

## 5. 실제 수정 전에 필요한 검수

- **음원 확인:** 129.56초 WAV를 구간별로 청음하여 **타격할 악기/소리, 반복 모티프, 박자 전환, 의도적인 쉼**을 정한다. 자동 4대역 onset만으로 악기 이름·구절을 확정하지 않는다.
- **공격 위험 시각:** `mix_gate`, `rain`, `mix_cross`, `mix_ribbon`의 예고→발사→접근→충돌 가능 시각을 샘플링하고, 피노 충돌 원 반경 및 실제 이동 제한을 사용한다.
- **Play Mode:** 초심자/숙련자 기준 플레이, 피노 정지·이동, 빠른 좌우/상하 회피, 휠 중 회피, 60fps/저프레임, 일시정지 복귀, 음악과 입력의 0ms 일치 여부를 검증한다.
- **측정할 실패 사례:** 피노의 도달 가능한 안전 경로가 0개, 탄막 경고/노트/휠이 겹쳐 가려짐, 음악적 타격과 노트가 어긋남, 공격이 연속적으로 발동해 회복할 시간이 없음.

## 6. 적용 범위

이 문서 작성은 **분석과 우선순위 결정**까지다. 오디오 청음·실제 조작 경로를 검증하지 못한 상태에서 고치면 원래 의도된 채보/탄막을 오히려 해칠 수 있어, **게임 파일의 박자·버튼·위치·공격 시각을 아직 수정하지 않았다.** 다음 실제 편집 시 먼저 25–26s, 70–72s, 97–105s, 112–122s를 검증하고, 변경 전후 재생/A-B로 채택 여부를 판단한다.
